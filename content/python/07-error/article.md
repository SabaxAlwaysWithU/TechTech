## エラーは「どこで、何が」の手紙

エラーが出ると失敗した気分になりますが、エラーメッセージは Python からの「ここで、こういう理由で止まりました」という手紙です。慣れた人ほど、エラーをよく読んでから直します。

## エラーメッセージの読み方

パソコンで Python を動かすと、エラーは次のように表示されます。

```text
Traceback (most recent call last):
  File "shop.py", line 3, in <module>
    print("合計は" + total + "円")
TypeError: can only concatenate str (not "int") to str
```

読むのは**下から**です。

1. **最後の行**: エラーの種類(`TypeError`)と理由。いちばん大事
2. **その上**: 止まった行の中身
3. **line 3**: 何行目で止まったか

この練習場では、出力欄に「何行目か」と最後の行、日本語の補足を表示します。

## よく見るエラー

| エラー | 意味 | よくある原因 |
| --- | --- | --- |
| `SyntaxError` | 文法の誤り | `:` やカッコ、引用符の閉じ忘れ |
| `IndentationError` | 字下げの誤り | `:` の次の行を字下げしていない |
| `NameError` | その名前がない | つづり間違い、代入前に使った |
| `TypeError` | 値の種類が合わない | 文字列と数を `+` でつないだ |
| `IndexError` | 番号が範囲外 | 3個のリストの `[3]` |
| `KeyError` | 辞書にキーがない | キーのつづり間違い |
| `ValueError` | 値がおかしい | `int("abc")` |
| `ZeroDivisionError` | 0 で割った | 空のリストで平均を出した |

`SyntaxError` は実行する前に見つかるので、1行も実行されません。ほかのエラーは、その行に来たところで止まります。

エラーの行が正しく見えるときは、**1つ前の行**を見てください。閉じカッコを忘れると、Python は次の行まで読んでから「おかしい」と気づくことがあります。

## try / except: エラーに備える

ユーザーが入力した値のように、エラーが起きるかもしれないとわかっている場所では、止まらずに対処できます。

```python
text = "12a"
try:
    number = int(text)
    print(f"{number}個ですね")
except ValueError:
    print("数字で入力してください")
print("処理を続けます")
```

- `try:` の中で、エラーが起きるかもしれない処理をする
- エラーが起きたら、その時点で `except` の中に飛ぶ
- エラーが起きなければ、`except` の中は実行されない

`text` を `"12"` にすると「12個ですね」、`"12a"` だと「数字で入力してください」になります。どちらでも、最後の行まで止まらずに進みます。

`except` のあとに書くのは、対処するエラーの種類です。種類を書かない `except:` はすべてのエラーを受け止めますが、つづり間違いの `NameError` まで隠れてしまうので、種類を書くのがよい習慣です。

関数の中で使うと、「失敗したら代わりの値を返す」関数が作れます。

```python
def to_int(text):
    try:
        return int(text)
    except ValueError:
        return 0

print(to_int("42"))
print(to_int("よんじゅうに"))
```

## raise: 自分でエラーを出す

関数に、受け付けられない値が渡されたときは、自分でエラーを出して知らせることもできます。

```python
def set_age(age):
    if age < 0:
        raise ValueError("年齢はマイナスにできません")
    return age

print(set_age(20))
print(set_age(-1))
```

`raise エラーの種類("理由")` で、その場でエラーにします。おかしな値のまま先に進んで、あとでわかりにくい失敗をするより、早く止めたほうが原因を見つけやすくなります。

## まとめ

- エラーメッセージは下から読む。最後の行が種類と理由、その上が行番号
- エラーの行が正しく見えたら、1つ前の行も見る
- `try:` の中でエラーが起きたら `except 種類:` に飛ぶ。種類は書く
- `raise ValueError("理由")` で自分からエラーを出せる
