title: 秘密の情報の扱い
description: API キーやパスワードをコードに書かない。環境変数、ログに残さない、漏れたら取り替える
---

## コードに書いた秘密は、漏れる

外部の API を使うときの **API キー**、データベースのパスワード、決済サービスの秘密の鍵。こうした**秘密の情報**を、プログラムの中にそのまま書いてしまうのは、よくある事故の始まりです。

```text
const API_KEY = "abcd-1234-ffff-0000";   ← これを GitHub に push すると…
```

- GitHub に push すると、公開リポジトリなら世界中から見える。秘密の鍵を探して回るプログラムが、push から数分で見つけることもある
- 非公開リポジトリでも、その鍵を知る人が増える
- 一度コミットすると、あとで消しても Git の履歴に残る(Git の分野の「履歴」)

ブラウザで動く JavaScript に書いたものは、**誰でも開発者ツールで読めます**(JavaScript の分野の「fetch と API」)。秘密の鍵は、ブラウザに渡してはいけません。

## 環境変数に置く

秘密の情報は、コードではなく、プログラムを動かす場所の設定、**環境変数**に置きます。

```text
Python:   os.environ["API_KEY"]
Node.js:  process.env.API_KEY
```

手元で動かすときは `.env` というファイルに書き、`.gitignore` に入れて Git に入らないようにします。公開するときは、Render や GitHub Actions などのサービスの設定画面(Secrets)に登録します。こうすれば、コードを公開しても、鍵は入っていません。

## ログに残さない

もう1つの漏れ道が**ログ**です。エラーの調べ物のために、届いたデータを丸ごとログに書くと、パスワードやカード番号までログに残ってしまいます。ログは、多くの人が見たり、別のサービスに送られたりするものです。

```js
function redact(line) {
  return line.replace(/(password|token)=[^&\s]+/g, "$1=***");
}
console.log(redact("POST /login name=tanaka&password=hello123"));
```

ログに書く前に、秘密の部分を `***` に置き換えます(正規表現の分野の「置き換え」)。どうしても見分けたいときは、`abcd****` のように最初の数文字だけを残します。

## 漏れたら、すぐ取り替える

それでも漏れてしまったら、**すぐにその鍵を無効にして、新しい鍵に取り替え**ます。コミットを消すだけでは足りません(履歴や、誰かの手元のコピーに残っているため)。

- API キーは、サービスの管理画面で無効にして作り直す
- パスワードは変える
- 何に使われたか、ログで確かめる

「漏れない作り」と同じくらい、「**漏れたときにすぐ取り替えられる作り**」が大事です。鍵がコードに書いてあると、取り替えるたびにコードを直して公開し直すことになりますが、環境変数なら設定を変えるだけで済みます。

## まとめ

- API キーやパスワードをコードに書かない。push すれば見つかり、履歴にも残る
- ブラウザの JavaScript に秘密を書かない(誰でも読める)
- 秘密は環境変数に。手元は .env(.gitignore に入れる)、公開先は Secrets の設定
- ログに秘密を残さない。漏れたら、すぐ無効にして取り替える
