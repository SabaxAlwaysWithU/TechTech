## ログインしたままでいられるしくみ

HTTP は、1回1回のやりとりが独立していて、前のやりとりを覚えていません。それでも、一度ログインすれば次のページでもログインしたままでいられるのは、**Cookie**(クッキー)と**セッション**のおかげです。

1. ログインに成功すると、サーバーはランダムで長い番号(**セッション ID**)を作り、「この番号は tanaka さん」と覚えておく
2. その番号を Cookie としてブラウザに渡す
3. ブラウザは、そのサイトに何かを送るたびに、Cookie を**自動で**付けて送る
4. サーバーは、届いた番号から「tanaka さんだ」とわかる

セッション ID は、**ログインそのものの代わり**です。盗まれたら、パスワードを知らなくてもなりすましができてしまいます。だから、推測できないランダムな値にし、HTTPS でだけ送ります。

## Cookie に付ける3つの印

Cookie を渡すときには、安全のための印を付けます。

```js
function sessionCookie(id) {
  return `session=${id}; HttpOnly; Secure; SameSite=Lax`;
}
console.log(sessionCookie("8f3a…"));
```

| 印 | 意味 |
| --- | --- |
| `HttpOnly` | ページの JavaScript から読めなくする。XSS されても、セッション ID は盗まれにくい |
| `Secure` | HTTPS のときだけ送る。通信の途中で盗み見られない |
| `SameSite=Lax` | 別のサイトから送られるリクエストには、基本的に付けない(下の CSRF 対策) |

## CSRF: 別のサイトから、勝手に送らせる

ブラウザが Cookie を「自動で」付けることには、落とし穴があります。

あなたがネットショップにログインしたまま、別の怪しいサイトを開いたとします。そのページに、こんなフォームが隠れていたらどうでしょう。

```text
<form action="https://shop.example/api/address" method="POST">
  <input name="address" value="攻撃者の住所">
</form>
<script> document.forms[0].submit(); </script>
```

ページを開いただけで、フォームが勝手にネットショップへ送られます。ブラウザは、ネットショップの Cookie を自動で付けるので、ショップから見ると「**ログインしているあなた本人が、住所を変えた**」ように見えます。これが **CSRF**(クロスサイトリクエストフォージェリ)です。

## 守り方: 本物の画面から来たかを確かめる

CSRF を防ぐには、「そのリクエストが、**自分のサイトの画面から**送られたものか」を確かめます。

- **CSRF トークン**: 自分のサイトのフォームに、セッションごとのランダムな値を隠しておく。リクエストに同じ値が付いていなければ断る。別のサイトはこの値を知らないので、送らせられない
- **Origin を確かめる**: ブラウザがリクエストに付ける `Origin`(どのサイトから送られたか)が、自分のサイトかを確かめる
- **SameSite の Cookie**: 別のサイトからのリクエストには Cookie を付けない
- **大事な操作は GET で受けない**: GET はリンクや画像からでも送られてしまう。変更は POST などで受ける

Django や Rails は、CSRF トークンのしくみを最初から持っていて、フォームに自動で入れてくれます。自分で API を作るときは、これらを組み合わせて確かめます。

## まとめ

- ログインしたままでいられるのは、Cookie に入れたセッション ID のおかげ。セッション ID はログインの代わりなので、盗まれないように守る
- Cookie には HttpOnly、Secure、SameSite を付ける
- CSRF は、別のサイトから、ログイン中の利用者のブラウザに勝手に送らせる攻撃
- CSRF トークン、Origin の確認、SameSite、変更を GET で受けない、で防ぐ
