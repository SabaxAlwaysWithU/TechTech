## 頼まれごと

知り合いが作った「ひとこと掲示板」を、公開する前に安全点検してほしいと頼まれました。見てみると、気になるところが5つあります。

1. 書き込みを `innerHTML` で画面に出している
2. 書き込みの長さや中身を確かめていない
3. 管理者のパスワードを、そのまま比べている
4. 書き込みの API が、どこから送られたものでも受け付けている
5. ログに、届いたデータを丸ごと書いている

練習場の5つの課題が、この5つです。課題1は画面の課題で、ほかは関数を作る課題です。

## 使う知識

| 点検するところ | 直し方 | レッスン |
| --- | --- | --- |
| 1 書き込みの表示 | textContent | XSS |
| 2 書き込みの中身 | 許すものを決めて確かめる | 安全なWebアプリの考え方 |
| 3 パスワード | ソルト付きのハッシュで比べる | パスワードの保存 |
| 4 書き込みの API | CSRF トークンと Origin | なりすましを防ぐ |
| 5 ログ | 秘密を *** に置き換える | 秘密の情報の扱い |

## 攻撃する人の気持ちで見る

点検するときは、「**ここに変なものを入れたら、どうなるか**」と、攻撃する人の気持ちで1つずつ見ていきます。

- 入力欄に `<img src=x onerror=...>` を入れたら?
- 名前を空にしたら? とても長くしたら?
- データベースが盗まれたら、パスワードはどうなる?
- 別のサイトから、この API に送られたら?
- ログを見た人に、何が見えてしまう?

1つの守りだけに頼らないこと(多層防御)も思い出してください。たとえば、書き込みを確かめていても、表示では textContent を使います。

## 詰まったら

- 判定のメッセージに、どの確かめで違ったかが出る
- 課題の初期状態のコードは「よくある危ない書き方」になっている。どこが危ないかを、まず言葉にしてみる
- 練習場の中でだけ、攻撃を試してよい
