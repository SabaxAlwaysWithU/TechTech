## 盗まれる前提で考える

SQL の分野の練習場では、`users` 表にパスワードがそのまま入っていました。もし本物のサイトがこうだと、データベースが一度でも盗まれたら、全員のパスワードがそのまま知られてしまいます。多くの人は同じパスワードをいくつものサイトで使い回しているので、被害はほかのサイトにも広がります。

だから、サーバーは**パスワードをそのまま保存しません**。「データベースはいつか盗まれるかもしれない」という前提で作ります。

## ハッシュ: 元に戻せない変換

**ハッシュ関数**は、文字列から、決まった長さの「指紋」のような値を作る計算です。

- 同じ入力からは、いつも同じ値ができる
- 1文字でも違えば、まったく違う値になる
- 値から元の入力に**戻すことはできない**

```js
// 練習用の小さなハッシュ関数(本物のサイトでは使えない。しくみを見るためのもの)
function hash(text) {
  let h = 2166136261;
  for (const ch of text) {
    h ^= ch.codePointAt(0);
    h = Math.imul(h, 16777619) >>> 0;
  }
  return h.toString(16).padStart(8, "0");
}
console.log(hash("hello123"));
console.log(hash("hello124"));
console.log(hash("hello123"));
```

サーバーは、パスワードのハッシュだけを保存します。ログインのときは、入力されたパスワードを同じようにハッシュして、保存してある値と同じかを比べます。パスワードそのものは、どこにも残りません。

## ソルト: 同じパスワードでも違う値に

ハッシュだけでは、まだ弱点があります。同じパスワードからは同じ値ができるので、攻撃者は「よく使われるパスワード何百万個のハッシュの一覧」を作っておき、盗んだ値と照らし合わせられます。`hello123` を使っている人は、すぐにばれてしまいます。

そこで、利用者ごとに違うランダムな文字列(**ソルト**、塩)を作り、パスワードにくっつけてからハッシュします。ソルトはハッシュと一緒に保存しておきます。

```text
保存するもの: { name: "tanaka", salt: "x7Qp", hash: hash("x7Qp" + "hello123") }
```

これで、同じ `hello123` でも、人ごとにまったく違う値になり、一覧での照らし合わせが使えなくなります。

## 本物では「わざと遅い」ハッシュを使う

もう1つ大事なことがあります。ふつうのハッシュ関数(上の練習用や、SHA-256 など)は**速すぎる**のです。攻撃者は、1秒に何十億回もハッシュを計算して、パスワードを総当たりで試せます。

パスワードの保存には、**わざと計算に時間がかかるように作られた**専用の方法を使います。代表は **bcrypt**、**scrypt**、**Argon2** です。1回の計算に 0.1 秒かかれば、ログインする人には気にならない遅さですが、総当たりする攻撃者には何万倍も遅くなります。しかも、ソルトも自動で付けてくれます。

自分でハッシュの仕組みを作らず、言語やフレームワークが用意している、これらの関数を使ってください(Django や Rails は、最初からそうなっています)。

## まとめ

- パスワードはそのまま保存しない。データベースは盗まれる前提で作る
- ハッシュは元に戻せない変換。保存するのはハッシュだけで、ログインのときは同じようにハッシュして比べる
- ソルトを付けると、同じパスワードでも人ごとに違う値になる
- 本物では bcrypt や Argon2 のような、わざと遅い専用の関数を使う
