## Web アプリは、知らない人が触る

自分のパソコンで動かすプログラムと違って、Web アプリは**世界中の誰でも**触れます。その中には、わざと変な入力をして、ほかの人の情報を盗んだり、サイトを壊したりしようとする人もいます。

SQL の分野で体験した SQL インジェクションは、その代表です。入力欄に `' OR 1=1 --` と打つだけで、パスワードなしでログインできてしまいました。この分野では、Web アプリでよくある攻撃と、その守り方を、練習場の中で体験しながら見ていきます。

## いちばん大事な原則: 入力を信用しない

ほとんどの攻撃は、「**利用者からの入力を、そのまま信用して使った**」ところから始まります。入力とは、フォームに打たれた文字だけではありません。

- URL の `?id=3` のような部分
- Cookie、ヘッダーなど、ブラウザが送ってくるもの全部
- アップロードされたファイルの名前や中身
- 外部の API から受け取ったデータ

ブラウザの JavaScript で入力を確かめても、開発者ツールを使えば飛ばせます(JavaScript の分野の「フォームを受け取る」)。**サーバーに届いたものは、必ずサーバーでもう一度確かめる**のが決まりです。

## 「だめなもの」ではなく「よいもの」を決める

入力を確かめるとき、「危ない文字を探して消す」(**拒否リスト**)は、抜け道が見つかりがちです。攻撃する人は、思いつかなかった書き方を探してくるからです。

それより、「**許すものだけを決めて、それ以外は全部断る**」(**許可リスト**)ほうが安全です。

```js
function orderColumn(input) {
  const allowed = ["name", "price", "id"];
  return allowed.includes(input) ? input : "id";
}
console.log(orderColumn("price"));
console.log(orderColumn("price; DROP TABLE users"));
```

並び順に使う列の名前を、利用者が選べるとします。決められた3つ以外が来たら、ふつうの `id` にしてしまいます。何が来ても、許可リストの外のものは使われません。

数を受け取るなら、「数字だけで、範囲も決まっている」ことを確かめてから使います。

```js
function quantity(input) {
  if (!/^\d{1,2}$/.test(input)) return null;
  const n = Number(input);
  return n >= 1 && n <= 99 ? n : null;
}
console.log(quantity("3"), quantity("-1"), quantity("1e9"), quantity("3abc"));
```

## 守りは何重にも

1つの守りだけに頼らず、何重にも重ねることを**多層防御**といいます。入力を確かめ、データベースにはプレースホルダで渡し、画面に出すときはエスケープし、データベースの権限も絞る。どれか1つが破られても、次で止められるようにします。

## 攻撃を試してよい場所

この分野で見る攻撃は、**自分の作ったアプリと、この練習場の中だけ**で試してください。他人のサイトで試すのは、結果にかかわらず不正アクセスとして犯罪になります。攻撃を知るのは、守るためです。

## まとめ

- Web アプリは誰でも触れる。入力(フォーム、URL、Cookie、ファイル)は信用しない
- ブラウザでの確認は飛ばせる。サーバーでもう一度確かめる
- 「だめなものを探す」より「許すものを決める」(許可リスト)
- 守りは何重にも(多層防御)。攻撃を試すのは自分のアプリと練習場だけ
