## HTML を組み立てるときは

前のレッスンでは、`textContent` で文字として入れれば安全でした。でも、サーバーで HTML を組み立てるときや、テンプレートの文字列でまとめて HTML を作るときは、`textContent` が使えません。

```js
const name = "さば";
const html = `<li><strong>${name}</strong> さん</li>`;
console.log(html);
```

ここに `name` として `<script>…</script>` が来たら、それもそのまま HTML になってしまいます。そこで、組み立てる前に、HTML で特別な意味のある記号を、**同じ見た目の「ただの文字」の書き方**に置き換えます。これを**エスケープ**といいます。正規表現の分野で `\.` と書いたのと同じ考え方です。

## 置き換える5つの記号

| 記号 | 置き換え先 | 理由 |
| --- | --- | --- |
| `&` | `&amp;` | `&` 自体が、この置き換えの書き方の始まりの印だから |
| `<` | `&lt;` | タグの始まり |
| `>` | `&gt;` | タグの終わり |
| `"` | `&quot;` | 属性の値の区切り |
| `'` | `&#39;` | 属性の値の区切り |

`&lt;` は、ブラウザで表示すると `<` に見えますが、タグの始まりとしては読まれません。

```js
function escapeHtml(s) {
  return s
    .replaceAll("&", "&amp;")
    .replaceAll("<", "&lt;")
    .replaceAll(">", "&gt;")
    .replaceAll('"', "&quot;")
    .replaceAll("'", "&#39;");
}
console.log(escapeHtml('<img src="x" onerror="alert(1)">'));
console.log(escapeHtml("Tom & Jerry"));
```

## & をいちばん最初に

順番には決まりがあります。**`&` を最初に**置き換えます。もし `<` を先に `&lt;` にしてから `&` を置き換えると、`&lt;` の `&` まで `&amp;` になり、`&amp;lt;` という二重の置き換えになってしまいます。画面には `<` ではなく `&lt;` と表示されてしまいます。

## どこに入れるかで、置き換え方が変わる

エスケープは、**値を入れる場所に合わせて**行います。

- HTML の本文や属性の値 → 上の5つを置き換える
- SQL の中 → エスケープではなく、プレースホルダで値として渡す(SQL の分野)
- URL の中 → `encodeURIComponent`(`&` や `?` などを `%26` のような形にする)
- JavaScript の文字列の中に値を埋め込む → そもそも避ける

「どこでも効く万能のエスケープ」はありません。入れる場所ごとに、その場所の決まりで置き換えます。

## いつエスケープするか

エスケープは、**出力する直前**に行うのが基本です。データベースには書き込まれたとおりに保存しておき、HTML に出すときに HTML 用に、URL に入れるときに URL 用に置き換えます。保存するときに置き換えてしまうと、HTML 以外に使うときに困り、二重に置き換える事故も起きやすくなります。

フレームワークのテンプレート(Django、Rails、Astro など)は、値を出すときに自動で HTML 用のエスケープをしてくれます。自分で HTML の文字列を組み立てるときだけ、自分でエスケープします。

## まとめ

- HTML を文字列で組み立てるときは、入れる値をエスケープする
- `& < > " '` の5つを置き換える。`&` を最初に
- 置き換え方は入れる場所で変わる。SQL はプレースホルダ、URL は encodeURIComponent
- エスケープは出力の直前に。保存はそのままの形で
