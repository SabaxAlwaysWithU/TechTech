## 「最終版_修正2_本当に最終.docx」

レポートを書いていて、こんなファイル名を付けたことはないでしょうか。直す前の版も残しておきたいから、コピーして名前を変える。気づけば似た名前のファイルが10個になり、どれが最新か分からなくなる。

プログラムを書くときは、この問題がもっと深刻です。1つのアプリが何十、何百のファイルでできていて、毎日少しずつ変わっていくからです。「昨日は動いていたのに」と思ったとき、昨日の状態に戻れないと困ります。

**Git** は、この「いつ、何を、どう変えたか」を記録して、いつでも戻れるようにする道具です。

## セーブポイント

ゲームのセーブに似ています。区切りのいいところでセーブしておけば、失敗してもそこからやり直せます。Git では、このセーブを**コミット**と呼びます。

コミットには、その時点の全ファイルの状態と、「何をしたか」の短いメモ(メッセージ)、日時、誰がしたかが記録されます。コミットを重ねると、プロジェクトの**履歴**ができあがります。

```
○ 写真を追加
│
○ 自己紹介の文を直す
│
○ 最初のページを作る   ← いちばん古いコミット
```

履歴があると、こんなことができます。

- 昨日の状態に戻す
- どこを変えたせいで壊れたのかを探す
- 2人で同じファイルを直しても、あとで合流させる

## リポジトリ

履歴をしまっておく場所を**リポジトリ**と言います。プロジェクトのフォルダの中に `.git` という隠しフォルダが作られ、そこに全部の履歴が入ります。

リポジトリは2か所にあります。

| 場所 | 名前 | 役割 |
| --- | --- | --- |
| 自分のパソコンの中 | **ローカル**リポジトリ | 普段の作業とコミットはここ |
| インターネット上(GitHub など) | **リモート**リポジトリ | 共有と公開、バックアップ |

ローカルで作ったコミットを、リモートに送るのが **push**(プッシュ)です。レッスン5で扱います。GitHub は、リモートリポジトリを置けるWebサービスで、世界中の開発者がコードを公開・共有しています。

## 用語の整理

| 言葉 | 意味 |
| --- | --- |
| Git | 履歴を記録する道具(コマンド) |
| GitHub | リモートリポジトリを置けるサービス(Webサイト) |
| リポジトリ | 履歴の入れ物。プロジェクトごとに1つ |
| コミット | 1回のセーブ |
| push | ローカルのコミットをリモートに送る |

Git と GitHub は別物です。Git がなくても GitHub は使えませんが、GitHub がなくても Git は使えます。

## 始め方: git init

プロジェクトのフォルダに移動して `git init` と打つと、そのフォルダがリポジトリになります。

```sh
cd project
git init
```

「Initialized empty Git repository」と出れば成功です。まだコミットは1つもない、空の履歴ができました。状態を見るには `git status` です。

```sh
git status
```

「Untracked files(まだ追跡していないファイル)」として、フォルダの中のファイルが並びます。Git はまだ、どのファイルも記録していません。次のレッスンで、最初のコミットを作ります。

## まとめ

- Git は「いつ、何を、どう変えたか」を記録し、いつでも戻れるようにする道具
- 1回のセーブがコミット。コミットの積み重ねが履歴
- 履歴の入れ物がリポジトリ。ローカル(手元)とリモート(GitHub)がある
- `git init` でフォルダをリポジトリにし、`git status` で状態を見る
