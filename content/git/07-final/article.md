## 1つのプロジェクトを最後まで

ホームの `project` は、自己紹介ページを作るプロジェクトです。これを Git で管理し始めて、GitHub に公開するまでを、4つの場面に分けて通しでやります。

1. **始める**: Git の管理を始め、いらないもの(`node_modules`)は入れずに、最初のコミットをする
2. **やり直す**: 2つのファイルを変えたが、片方は間違いだった。間違いだけを取り消し、正しい変更だけをコミットする
3. **分けて作る**: 見た目の変更をブランチで作り、できたら main に取り込む
4. **公開する**: GitHub につないで push し、そのあとの更新も push する

練習場の4つの課題が、この4つの場面です。課題ごとに、その場面の直前の状態から始まります。

## いつも状態を見る

Git で迷ったときの合言葉は「とりあえず `git status`」です。

- 今どのブランチにいるか
- 変更したのに、まだステージしていないファイル(赤)
- ステージ済みで、次のコミットに入るファイル(緑)
- Git がまだ知らないファイル(Untracked)

が一度に分かります。コマンドを打つたびに `git status` で確かめる癖をつけると、「思っていたファイルがコミットに入っていない」といった事故を防げます。

## 使う道具のおさらい

| やりたいこと | コマンド | レッスン |
| --- | --- | --- |
| 管理を始める / 状態を見る | `git init`、`git status` | Gitとは何か |
| 入れないファイルを決める | `.gitignore` に書く | 日々の使い方 |
| ステージ / コミット | `git add`、`git commit -m "…"` | add と commit |
| 変更を取り消す | `git restore ファイル` | 履歴を見る、戻す |
| ブランチ / 取り込み | `git switch -c 名前`、`git switch main`、`git merge 名前` | ブランチ |
| GitHub に送る | `git remote add origin URL`、`git push -u origin main`、`git push` | GitHub と push |

## 取り消しは「戻る先」を確かめてから

`git restore ファイル` は、そのファイルの変更を、最後のコミットの状態に戻します。戻した変更は元に戻せません。`git diff` で何が変わっているかを見てから、本当に要らない変更だけを戻しましょう。
