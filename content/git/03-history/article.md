## セーブしたのは戻るため

履歴を残す目的は、見返すことと、戻ることです。このレッスンでは、何が変わったかを見る `diff` と、変更をなかったことにする `restore` を覚えます。「Git を使っていれば壊しても戻せる」という安心感が、思い切って試す力になります。

## 履歴を見る: git log

```sh
git log --oneline
```

```
3f2a1c9 メモに次の予定を書く
8b7d4e0 最初のページを作る
a1b2c3d README を追加
```

新しいものが上です。左の7桁がコミットID、右がメッセージです。メッセージをちゃんと書いておくと、この一覧だけで歴史が読めます。

`--oneline` を外すと、日時と作者も表示されます。

## 変更を見る: git diff

ファイルを編集したあと、「どこを変えたんだっけ」を確かめるのが `git diff` です。

```sh
echo "趣味は料理です" >> README.md
git diff
```

```
--- a/README.md
+++ b/README.md
+趣味は料理です
```

`+` で始まる行が追加した行、`-` で始まる行が消した行です。`git diff` は「ステージしていない変更」を表示します。`add` したあとの変更を見るには `git diff --staged` です。

コミットする前に `git diff` で見直す習慣をつけると、消し忘れのデバッグ用コードや、うっかり変えた行に気づけます。

## 編集を取り消す: git restore

「直そうとしたら余計に壊した。さっきコミットした状態に戻したい」。こういうときは `git restore` です。

```sh
git restore README.md
```

`README.md` が、最後にコミット(またはステージ)した内容に戻ります。`git diff` を打っても何も出なくなります。

注意点が1つ。`restore` は**取り消しの取り消しができません**。コミットしていない編集は消えたら戻らないので、本当に捨てていいか確かめてから打ってください。迷ったら、先にコミットしておけば安全です。

## ステージから外す: git restore --staged

`add` したあとで「やっぱりこのファイルは次のコミットに入れない」と思ったら、`--staged` を付けます。

```sh
git add memo.txt
git restore --staged memo.txt
```

ファイルの中身はそのままで、ステージから外れるだけです。「Changes not staged for commit」に戻ります。

## 3つのコマンドの使い分け

| やりたいこと | コマンド |
| --- | --- |
| 何をコミットしてきたか見る | `git log --oneline` |
| 今どこを変えたか見る | `git diff` |
| 編集を捨てて、最後のコミットに戻す | `git restore ファイル` |
| add を取り消す(中身は残す) | `git restore --staged ファイル` |

## コミットそのものを戻すには

コミット済みの変更を取り消す方法(`git revert`、`git reset`)もありますが、履歴を書き換えるものもあり、チームで使うと事故のもとです。この分野では扱いません。「困ったら、履歴を壊さずに新しいコミットで直す」が初心者のうちの安全な方針です。

## まとめ

- `git log --oneline` で履歴を一覧。メッセージがよければそれだけで読める
- `git diff` で、まだステージしていない変更を見る。コミット前の見直しに使う
- `git restore ファイル` で編集を捨てて最後のコミットに戻す。取り消せないので注意
- `git restore --staged ファイル` で add だけ取り消す
