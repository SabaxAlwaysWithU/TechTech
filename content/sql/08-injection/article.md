## アプリは、入力から SQL を組み立てている

実際のアプリでは、利用者は SQL を書きません。ログイン画面に名前とパスワードを入れるだけです。その裏で、**アプリが入力を使って SQL を組み立てて**、データベースに送っています。

たとえば、こんなプログラムがあったとします(Python で書いた例です)。

```python
sql = "SELECT id, name, role FROM users WHERE name = '" + name + "' AND password = '" + password + "'"
```

名前に `tanaka`、パスワードに `hello123` と入れると、組み立てられる SQL はこうなります。

```text
SELECT id, name, role FROM users WHERE name = 'tanaka' AND password = 'hello123'
```

両方合う行があれば「ログイン成功」、なければ「ログイン失敗」。ふつうに使うぶんには、ちゃんと動きます。

## 引用符1つで、SQL が壊れる

では、名前に `'`(引用符)を1つだけ入れたらどうなるでしょう。

```text
SELECT id, name, role FROM users WHERE name = ''' AND password = 'x'
```

`'` は SQL では「文字列の始まりと終わり」の印です。入力した `'` が、SQL の文法の一部として読まれてしまい、引用符の組み合わせが崩れて、エラーになります。

これが問題の始まりです。**入力した文字が、ただのデータではなく、SQL の命令の一部として読まれている**のです。

## 入力で、条件を書き換える

文法として読まれるなら、入力で SQL を「書き足す」こともできます。名前に `admin' --` と入れると:

```text
SELECT id, name, role FROM users WHERE name = 'admin' --' AND password = 'x'
```

- `admin'` の `'` で、名前の文字列がそこで閉じる
- `--` は SQL の**コメント**(ここから行の終わりまでは無視)の印

その結果、パスワードの条件がまるごと無視され、「名前が admin の行」が返ってきます。**パスワードを知らないのに、管理者としてログインできてしまいます。**

名前すら知らなくても、`' OR 1=1 --` と入れれば:

```text
SELECT id, name, role FROM users WHERE name = '' OR 1=1 --' AND password = 'x'
```

`1=1` はいつも正しいので、全員の行が返ります。アプリは最初の行の人としてログインさせることが多く、たいていそれは最初に作られた管理者です。

このように、入力に SQL を混ぜて、アプリが送る SQL を書き換えてしまう攻撃を、**SQL インジェクション**(SQL の注入)といいます。

## ログイン以外も危ない

被害はログインだけではありません。商品の検索画面が、こう SQL を組み立てていたとします。

```text
SELECT name, price FROM products WHERE name LIKE '%(入力)%'
```

ここに `' UNION SELECT name, password FROM users --` と入れたとします。`UNION` は、2つの `SELECT` の結果を縦につなげる命令です(列の数がそろっている必要があります)。商品の検索結果のうしろに、**別の表の中身**がつながって表示されます。会員の名前とパスワードが、商品の一覧として画面に出てしまうのです。

`;` で文をつなげられる作りだと、`'; DROP TABLE users; --` で表を消されることもあります。実際に、SQL インジェクションで大量の個人情報が盗まれた事件が、国内外で何度も起きています。

## 防ぎ方: プレースホルダ

根本の原因は、「入力を SQL の文字列の中に、そのまま貼り付けている」ことです。防ぎ方は、**入力を SQL に貼り付けず、値として別に渡す**ことです。

```python
cur.execute(
    "SELECT id, name, role FROM users WHERE name = ? AND password = ?",
    (name, password),
)
```

SQL の中の `?` を**プレースホルダ**(場所取り)といいます。データベースは、まず `?` の入った SQL の形を読んでから、`?` の場所に入力を「ただの値」としてはめ込みます。入力に `'` や `--` が入っていても、それは「名前が `admin' --` という人」を探すだけで、SQL の文法には一切影響しません。

Django や Rails などのフレームワークの、データベースを扱う機能(ORM)は、中で自動的にプレースホルダを使っています。自分で SQL を書くときは、文字列をつなげずにプレースホルダ、と覚えてください。

## ほかにも大事なこと

- **自分でエスケープしない**。「`'` を消す」のような自作の対策は抜け道が見つかりがち
- **パスワードはそのまま保存しない**。練習場の `users` 表はわかりやすさのためにそのまま入れていますが、本物では元に戻せない形(ハッシュ)にする
- **エラーの中身を見せない**。SQL のエラーは攻撃の手がかりになる。練習場ではわざと見せています
- **データベースの権限を絞る**。アプリには、表を消す権限などを与えない

## 試してよいのは、ここだけ

他人のサイトのログイン画面に `' OR 1=1 --` を入れて試すのは、**不正アクセスで、犯罪**です(不正アクセス禁止法など)。「入るつもりはなかった」「確かめただけ」でも許されません。

攻撃のしかたを知るのは、自分が作るアプリを守るためです。試すのは、この練習場や、自分の手元に作った練習用の環境だけにしてください。

## まとめ

- アプリは入力から SQL を組み立てている。入力をそのまま貼り付けると、入力が SQL の命令として読まれる
- `'` で文字列を閉じ、`--` で残りを無視させ、`OR 1=1` や `UNION` で条件や結果を書き換えるのが SQL インジェクション
- 防ぎ方はプレースホルダ(`?`)。入力を SQL に貼り付けず、値として別に渡す
- パスワードはハッシュにして保存し、エラーの中身は見せず、権限は絞る
- 試してよいのは、練習場と自分の環境だけ
