## ここまでで何ができるようになったか

表を読み(`SELECT`)、絞り(`WHERE`)、並べ(`ORDER BY`)、まとめ(`GROUP BY`)、つなぎ(`JOIN`)、変える(`INSERT`、`UPDATE`、`DELETE`)。ここまでで、データベースを使う上での基本はそろいました。

最後のレッスンでは、実際の仕事で必ず出てくる2つの仕組みを紹介します。速くするための**インデックス**と、安全にするための**トランザクション**です。

## インデックス: 探すのを速くする

分厚い辞書で「りんご」を引くとき、1ページ目から順に読む人はいません。「ら行」の見出しを頼りに、一気に近くまで飛びます。

データベースも同じです。何も用意しなければ、`WHERE customer_id = 2` のような検索は、表を1行目から最後まで全部見て探します。行が15行ならすぐ終わりますが、1,000万行あると目に見えて遅くなります。

**インデックス**は、この「見出し」をあらかじめ作っておく仕組みです。

```sql
CREATE INDEX idx_orders_customer ON orders (customer_id);
```

`CREATE INDEX 名前 ON 表 (列)` の形です。これで `orders` 表の `customer_id` に見出しが付き、`WHERE customer_id = 2` が一気に速くなります。

主キーには最初からインデックスが付いています。`WHERE id = 10` が速いのはそのためです。

ただし、インデックスは万能ではありません。見出しを作る分だけ保存場所を使い、行を足したり変えたりするたびに見出しも更新されるので、書き込みは少し遅くなります。「よく検索に使う列」にだけ付けるのが基本です。

練習場のデータは小さいので速さの違いは体感できませんが、書き方は同じです。

## トランザクション: まとめて成功か、まとめて失敗か

銀行の振込を考えてください。AさんからBさんへ1万円送るには、2つの変更が必要です。

1. Aさんの残高を1万円減らす
2. Bさんの残高を1万円増やす

1が終わった直後に停電したらどうなるでしょう。Aさんのお金だけが減って、Bさんには届きません。これは絶対に避けなければいけません。

**トランザクション**は、複数の変更を「全部成功するか、全部なかったことにするか」のどちらかにする仕組みです。途中で止まることはありません。

```sql
BEGIN;
UPDATE orders SET status = '発送済' WHERE id = 17;
UPDATE orders SET status = '発送済' WHERE id = 18;
COMMIT;
```

`BEGIN` で始め、`COMMIT` で確定します。`COMMIT` するまでは、変更は仮の状態です。

途中で「やっぱりやめた」と思ったら、`COMMIT` の代わりに `ROLLBACK` と書きます。`BEGIN` 以降の変更がすべて取り消されます。

```sql
BEGIN;
DELETE FROM orders;
-- 間違えた。全部消してしまう
ROLLBACK;
```

`ROLLBACK` のあとに `SELECT COUNT(*) FROM orders;` を実行すると、20行のまま残っています。レッスン5で「`DELETE` に取り消しはない」と書きましたが、トランザクションの中なら `COMMIT` するまでは取り消せるわけです。

## この先に進むには

この分野で学んだSQLは、どのデータベース製品でもほぼそのまま使えます。練習場で使っている SQLite のほか、MySQL、PostgreSQL などが広く使われていますが、`SELECT` や `JOIN` の書き方は共通です。

次に学ぶなら、次のような話題があります。

- **サブクエリ**: `SELECT` の中に `SELECT` を書く
- **ビュー**: よく使う `SELECT` に名前を付けて表のように扱う
- **プログラムからの利用**: Python や JavaScript からSQLを実行する

## まとめ

- `CREATE INDEX` で検索を速くする。よく検索する列にだけ付ける
- `BEGIN` → 変更 → `COMMIT` で、複数の変更をまとめて確定する
- 途中でやめるなら `ROLLBACK`。`BEGIN` 以降が取り消される
