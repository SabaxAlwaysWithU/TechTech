## 言語ごとの書き方

正規表現そのものは、どこでもほとんど同じです。使う道具の呼び方が少しずつ違います。

| やりたいこと | Python(re) | JavaScript |
| --- | --- | --- |
| 一致するか | `re.search(r"\d+", s)` | `/\d+/.test(s)` |
| 全体が一致するか | `re.fullmatch(r"\d+", s)` | `/^\d+$/.test(s)` |
| 全部取り出す | `re.findall(r"\d+", s)` | `s.match(/\d+/g)` |
| 置き換える | `re.sub(r"\s+", " ", s)` | `s.replace(/\s+/g, " ")` |

Python では、パターンの文字列の前に `r` を付けて `r"\d+"` と書きます(raw 文字列)。付けないと、`\` が Python の文字列のほうの記号として先に読まれてしまうためです。JavaScript では `/ /` で囲み、うしろに `g`(全部)や `i`(大文字小文字を区別しない)などのフラグを付けます。

Linux のターミナルでは `grep` がそのまま正規表現で探します。

```text
grep -E "^[0-9]{3}-[0-9]{4}$" zipcodes.txt     ← 郵便番号の形の行だけを出す
grep -E "ERROR|WARN" app.log                    ← エラーか警告の行を出す
```

## メールアドレスの落とし穴

「メールアドレスかどうか」を確かめたくなることはよくあります。でも、メールアドレスの正式な決まりはとても複雑で、完全に正しい正規表現は、何百文字にもなります。

```text
^[\w.+-]+@[\w-]+\.[\w.-]+$
```

実際の仕事では、このくらいの「**だいたいの形**」を確かめるだけにして、本当に届くかは、確認のメールを送って確かめます。正規表現を厳しくしすぎると、`taro+shop@example.co.jp` のような、ちゃんと届くアドレスをはじいてしまいます。

## 読める正規表現にする

正規表現は短く書ける反面、あとから読むと何をしているかわかりにくくなりがちです。

- **小さく分けて、試しながら作る**。練習場のように、色が付く道具(regex101 などのサイト、VS Code の検索)で1つずつ足していく
- **確かめ用の文字列を用意する**。一致してほしいものと、してほしくないものの両方
- **コメントを付ける**。Python の `re.VERBOSE` を使うと、パターンの中に空白や `#` のコメントを書ける
- **正規表現にこだわらない**。カンマで分けるだけなら `split(",")`、決まった文字を探すだけなら `in` のほうが読みやすい

「正規表現で解決しようとしたら、問題が2つになった」という有名な冗談があるくらいです。強力な道具ですが、使いどころを選びましょう。

## 日本語を扱うとき

- Python の `\d` は、全角の数字(`１２３`)にも一致する。JavaScript の `\d` は半角だけ
- ひらがなは `[ぁ-ん]`、カタカナは `[ァ-ン]` のように範囲で書ける
- 全角と半角が混ざった入力は、正規表現の前に、そろえる処理(正規化)をすると楽になる

## まとめ

- 正規表現は言語共通。Python は re と `r"…"`、JavaScript は `/…/g`、ターミナルは grep
- メールアドレスは「だいたいの形」だけ確かめ、届くかは確認のメールで
- 小さく作って試す、確かめ用の文字列を用意する、コメントを付ける
- 簡単なことは split や in で。正規表現にこだわらない
