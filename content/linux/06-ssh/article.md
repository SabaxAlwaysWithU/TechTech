## サーバーは遠くにある

借りたクラウドのサーバーや VPS は、どこかのデータセンターにあって、画面もキーボードもつながっていません。それでも、あなたの手元のターミナルから、まるでそこに座っているかのようにコマンドを打てます。その仕組みが **SSH**(Secure Shell)です。

```sh
ssh saba@server
```

「server というコンピュータに、saba というユーザーとして入る」という意味です。つながると、プロンプトが `saba@web-server:~$` のように相手の名前に変わり、そこから打つコマンドはすべて遠くのサーバーで実行されます。通信はすべて暗号化されています(ポート22番)。

## パスワードより鍵

SSH はパスワードでもログインできますが、インターネットに出ているサーバーには、世界中から休みなくパスワードの総当たり攻撃が来ます。そこで、**鍵**を使うのが標準です。

鍵は2つで1組になっています。

| | 置き場所 | 扱い |
| --- | --- | --- |
| **秘密鍵** `id_ed25519` | 自分のパソコンだけ | 絶対に誰にも見せない |
| **公開鍵** `id_ed25519.pub` | サーバーに登録する | 見られても困らない |

公開鍵は「南京錠」、秘密鍵は「その鍵」だと考えてください。南京錠(公開鍵)はいくつ配っても、開けられるのは鍵(秘密鍵)を持っている自分だけです。サーバーは「この南京錠を開けられる人だけ入れる」と判断します。

## 3つの手順

**1. 鍵を作る**
```sh
ssh-keygen
```
`~/.ssh/id_ed25519`(秘密鍵)と `~/.ssh/id_ed25519.pub`(公開鍵)ができます。

**2. 公開鍵をサーバーに登録する**
```sh
ssh-copy-id saba@server
```
1回だけパスワードを聞かれ、公開鍵がサーバーの `~/.ssh/authorized_keys` に書き込まれます。クラウドでは、サーバーを作る画面で公開鍵を貼り付ける形が多いです。

**3. つなぐ**
```sh
ssh saba@server
```
今度はパスワードを聞かれずに入れます。1つだけコマンドを実行して帰ってくることもできます。

```sh
ssh saba@server hostname
```

## 鍵の権限が緩いと拒否される

秘密鍵は「自分しか読めない」状態でなければいけません。ほかの人が読める権限になっていると、SSH はその鍵を使うことを拒否します。

```
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@         WARNING: UNPROTECTED PRIVATE KEY FILE!          @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
Permissions 0644 for '/home/saba/.ssh/id_ed25519' are too open.
```

`0644` は OS分野で学んだ数字の権限で、`rw-r--r--`(他人も読める)です。鍵をコピーしたり、別のパソコンから持ってきたりしたときによく起きます。自分だけが読み書きできる `600` に直せば使えます。

```sh
chmod 600 ~/.ssh/id_ed25519
```

## よくあるエラー

| エラー | 原因 |
| --- | --- |
| `Permission denied (publickey)` | 公開鍵がサーバーに登録されていない、またはユーザー名が違う |
| `Permissions 0644 ... are too open` | 秘密鍵の権限が緩い。`chmod 600` |
| `Could not resolve hostname` | サーバーの名前が間違っている(DNS) |
| `Connection refused` | サーバーで SSH が動いていない、またはポートが閉じている |
| `Connection timed out` | サーバーに届かない(ネットワーク、ファイアウォール) |

下の3つは、ネットワーク分野で見たものと同じです。SSH も結局は「名前を引いて、つないで、話す」ことに変わりはありません。

## 守ること

- 秘密鍵はどこにもアップロードしない。GitHub に push しない
- サーバー側では、パスワードでのログインを禁止して、鍵だけにするのが定番
- root での直接ログインも禁止し、自分のユーザーで入ってから `sudo` を使う

## まとめ

- SSH は遠くのサーバーに安全につなぐ仕組み。`ssh ユーザー@サーバー`
- 鍵は秘密鍵(自分だけ)と公開鍵(サーバーに登録)の2つで1組
- `ssh-keygen` → `ssh-copy-id` → `ssh` の3手順
- 秘密鍵の権限は `600`。緩いと拒否される
