## 今日の当番はあなた

小さな会社の Web サーバーの「当番」を任されました。今日は朝から、いろいろ起こります。

1. 朝の点検: 記録(ログ)の中に、アプリの行がいくつあるか数えて報告する
2. 「ページが出ない」: nginx が止まっていて、しかも次に再起動したときにも自動で立ち上がらない設定になっている
3. 「ページが出ないうえに、ログも書けない」: ディスクがいっぱいで、nginx も止まっている
4. 新しく入った同僚のために、パスワードではなく鍵でサーバーへ入れるようにする

練習場の4つの課題が、この4つです。課題ごとに、サーバーは最初の状態(その課題の困った状態)に戻ります。

## 調べる順番

トラブルのときは、いきなり直そうとせず、次の順で調べます。

1. **症状を確かめる**: `curl http://localhost/` で本当にページが出ないか
2. **状態を見る**: `systemctl status nginx` で動いているか、`df -h` でディスクに空きがあるか
3. **理由を読む**: `journalctl -u nginx` やログで、なぜそうなったか
4. **直す**: `sudo systemctl start nginx`、不要なファイルを `sudo rm` など
5. **もう一度確かめる**: 最初と同じ `curl` で、直ったことを見る

最後の「もう一度確かめる」を忘れないでください。直したつもりでも、別の原因が残っていることがあります。

## 使う道具のおさらい

| やりたいこと | コマンド | レッスン |
| --- | --- | --- |
| 行を絞る / 数える | `grep 文字 ファイル`、`… \| wc -l` | パイプとテキスト処理 |
| サービスの状態 / 起動 | `systemctl status`、`sudo systemctl start` | サービスと systemctl |
| 起動時に自動で動かす | `sudo systemctl enable サービス` | サービスと systemctl |
| ディスクの空き / 大きいもの探し | `df -h`、`du -h -d 1 場所` | ログとトラブル対応 |
| 鍵を作る / 登録 / ログイン | `ssh-keygen`、`ssh-copy-id`、`ssh` | SSH |

## start と enable の違い

`start` は「今すぐ動かす」、`enable` は「次に電源を入れたとき、自動で動かす」です。片方だけでは足りない場面があります。start だけだと、サーバーを再起動したら止まったままになります。enable だけだと、今は止まったままです。課題2では両方が必要です。
