## 2つの心配

カフェの Wi-Fi でログインするとき、心配なことが2つあります。

1. **話している相手は本物か**: 途中で誰かが偽物のサーバーにすり替えていないか
2. **会話を盗み聞きされないか**: パスワードや入力内容を、同じ Wi-Fi の誰かに読まれないか

HTTP はただの文字なので、どちらも防げません。これを解決するのが **HTTPS** です。URL が `https://` で始まり、ブラウザに鍵のマークが出ます。

## 証明書: サーバーの身分証

1 を解決するのが**証明書**です。運転免許証のように、「このサーバーは `example.com` の持ち主です」と書かれた身分証で、サーバー(nginx)が接続のはじめにブラウザへ見せます。

自分で書いた身分証は信用できません。免許証が信じられるのは警察が発行しているからです。証明書も、**認証局**(CA)という信頼された機関が「確かにこのドメインの持ち主です」と確認して発行します。ブラウザやパソコンは、信頼できる認証局の一覧を最初から持っていて、一覧にない発行元の証明書は受け付けません。

証明書には次のことが書いてあります。

| 項目 | 例 |
| --- | --- |
| 誰のものか | `example.com` |
| 誰が発行したか | Let's Encrypt |
| いつまで有効か | 発行から90日 |
| 公開鍵 | 暗号化を始めるための鍵 |

## 暗号化: 2 の解決

身元が確かめられたら、ブラウザとサーバーは証明書に入っている鍵を使って、2人だけが知る合言葉を決めます。以後の会話はその合言葉で暗号化され、途中で読まれても意味のない文字にしか見えません。中で話している中身(`GET /`、`200 OK`)は HTTP と同じで、外側に暗号の封筒をかぶせているだけです。

ポートは HTTP の 80 ではなく **443** を使います。

## 証明書の期限切れ

証明書には有効期限があります。期限が切れると、ブラウザは「この接続ではプライバシーが保護されません」と赤い警告を出し、curl はこう言って止まります。

```
curl: (60) SSL certificate problem: certificate has expired
```

大事なのは、**サーバーは元気で、ネットワークもつながっている**ことです。止めているのはブラウザや curl の側で、「身分証が切れている相手とは話さない」と判断しています。実際、同じサーバーに `http://` でつなぐと普通に見られます。

curl には `-k` という「証明書の確認を飛ばす」オプションがあります。原因を調べるときには使えますが、偽物のサーバーとも話してしまうので、普段は使いません。

## Let's Encrypt と自動更新

昔は証明書が有料で、更新を忘れて期限切れになる事故がよくありました。今は **Let's Encrypt** という無料の認証局があり、`certbot` というコマンドで取得から更新までを自動化できます。VPS で nginx を立てるときの定番です。

GitHub Pages、Netlify、Vercel のようなサービスは、これを全部自動でやってくれます。TechTech の証明書も GitHub が管理していて、あなたは何もしていません。

## HSTS: 次からは必ず HTTPS で

HTTPS のサーバーは、返事のヘッダーにこう付けることがあります。

```
Strict-Transport-Security: max-age=31536000
```

「これから1年間は、うちには必ず HTTPS で来てください」という指示です。ブラウザが覚えて、うっかり `http://` で開こうとしても自動で `https://` に変えてくれます。

## まとめ

- HTTPS は「相手が本物か」と「盗み聞き」の2つを防ぐ。ポートは 443
- 証明書はサーバーの身分証。認証局が発行し、ブラウザは信頼できる発行元だけを信じる
- 期限が切れると `certificate has expired`。サーバーもネットワークも元気なのに、つながらない
- 今は Let's Encrypt で無料・自動更新。GitHub Pages などは全部やってくれる
