## 電話帳

友だちに電話するとき、番号を全部覚えている人はいません。名前で探して、電話帳が番号を教えてくれます。

インターネットの住所は `93.184.216.34` のような数字ですが、人間は覚えられないので `example.com` という**名前**を使います。名前を住所に変えてくれる電話帳が **DNS**(Domain Name System)です。

ブラウザに名前を打つたび、裏では必ず DNS に「この名前の住所は?」と聞いています。1回のアクセスの最初の1歩です。

## 誰に聞いているか

PC は、DNS サーバーの住所を1つ知っています。`ip addr` に出ていた `dns 8.8.8.8` がそれです。普通はルーターや DHCP が教えてくれる、プロバイダの DNS サーバーですが、Google の `8.8.8.8` や Cloudflare の `1.1.1.1` のような公開 DNS を使うこともできます。

DNS サーバーは、世界中の名前を1台で覚えているわけではありません。「`.com` の担当はあちら」「`example.com` の担当はそちら」と、何段かの問い合わせをして答えにたどり着き、答えをしばらく覚えておきます(キャッシュ)。だから2回目からは速いのです。

## 自分で引いてみる: nslookup

```sh
nslookup example.com
```

```
Server:   8.8.8.8
Address:  8.8.8.8#53

Non-authoritative answer:
Name:    example.com
Address: 93.184.216.34
```

上2行が「誰に聞いたか」、下2行が答えです。`#53` は DNS が使うポート番号で、次のレッスンで出てきます。

存在しない名前を聞くと、`NXDOMAIN`(そんなドメインはない)と返ってきます。URL を打ち間違えたときのエラーの正体です。

## DNS が壊れたときの症状

DNS だけが壊れると、独特なことが起きます。

```sh
curl http://example.com/
```
```
curl: (6) Could not resolve host: example.com
```

「名前を解決できない」。住所が分からないので、送る前に止まります。`ping example.com` なら `Temporary failure in name resolution` です。

ところが、住所を直接指定すると**つながります**。

```sh
curl http://93.184.216.34/
```

電話帳が壊れていても、番号を知っていれば電話はかけられるのと同じです。「名前では失敗するが、IP では成功する」なら、壊れているのは DNS だけで、回線もサーバーも生きていると分かります。これが DNS の故障を見分ける決め手です。

## DNS が原因のよくあるトラブル

- 「どのサイトも開けないのに、LINE は届く」: LINE は IP を直接使うことが多く、DNS が死んでいても動く。Web だけ全滅なら DNS を疑う
- 「引っ越したばかりのサイトが古いページを出す」: DNS のキャッシュが古い住所を覚えている。しばらく待つと直る
- 「社内のサーバー名が家からだと引けない」: 社内 DNS にしか登録されていない名前。VPN が必要

## まとめ

- DNS は名前を IP アドレスに変える電話帳。アクセスの最初の1歩
- `nslookup 名前` で自分で引ける。存在しない名前は `NXDOMAIN`
- DNS だけが壊れると `Could not resolve host`。でも IP を直接指定すればつながる
- 「名前はだめ、IP は通る」なら犯人は DNS
