## 2種類の住所

IPアドレスは `192.168.1.10` のように、0〜255 の数を4つ並べた形です。実は、家の中で使う住所と、インターネットで使う住所は別物です。

| 種類 | 例 | 使われる場所 |
| --- | --- | --- |
| **プライベートIP** | `192.168.x.x`、`10.x.x.x` | 家や会社の中だけ。どの家でも同じ番号を使い回せる |
| **グローバルIP** | `93.184.216.34` | インターネット上で世界に1つ。サーバーや、あなたの家のルーターの外側 |

マンションの部屋番号(101号室)はどのマンションにもありますが、マンションの住所は世界に1つ、という関係です。家の中の PC やスマホは部屋番号(プライベートIP)しか持っておらず、外と話すときはルーターがマンションの住所(グローバルIP)で代わりに出ていきます。この仕組みを **NAT** と言います。

## IPアドレスは誰が決めるか

家の PC の `192.168.1.10` は、あなたが決めたわけではありません。PC がネットワークにつながったとき、ルーターが「あなたは 192.168.1.10 を使ってください」と**自動で配って**います。この仕組みが **DHCP** です。

DHCP がうまくいかないと、PC は住所を持てません。このとき PC は `169.254.x.x` という「仮の番号」を自分で付けますが、これではどこにも届きません。「Wi-Fi にはつながっているのにインターネットが使えない」の原因でよくあるものです。練習場で「IPアドレスの設定」を壊すと、この状態になります。

```sh
ip addr
```

`169.254.33.7` のような番号が出たら、DHCP に失敗しています。

## ルーター: 出入口

PC が外のサーバーにパケットを送るとき、「宛先は家の中ではない」と判断したら、とにかく**ルーター**に渡します。ルーターは家の中と外の両方に足を持っていて、外向きのパケットをプロバイダへ送り出し、返事を家の中の正しい PC に戻します。

ルーターの家側の住所が `192.168.1.1` で、PC からは**ゲートウェイ**(関門)と呼びます。`ip addr` の `gateway` に出ていたものです。

## 壊すと何が起きるか

練習場で壊して、エラーの違いを見てみましょう。

**ケーブルが抜けている、または IP をもらえていない**
```
ping: connect: Network is unreachable
```
「ネットワークに到達できない」。PC は自分がどこにもつながっていないと分かっているので、送る前にあきらめます。

**ルーターの電源が落ちている**
```
From 192.168.1.10 icmp_seq=1 Destination Host Unreachable
```
「宛先ホストに到達できない」。PC はケーブルの先に向かって「192.168.1.1 さん、いますか?」と呼びかけますが、誰も返事をしません。自分の住所(`From 192.168.1.10`)からの報告なのがポイントです。

**インターネット回線が切れている**
```
3 packets transmitted, 0 received, 100% packet loss
```
ルーターまでは届くので ping は送れますが、その先で消えて返事が来ません。黙って**タイムアウト**します。

同じ「つながらない」でも、3つとも文言が違います。文言を見れば、どこまで届いているかが分かります。

## 経路を1段ずつ見る: traceroute

パケットがどこまで進めたかを段階ごとに見せてくれるのが `traceroute` です。

```sh
traceroute example.com
```

1段目がルーター、2段目がプロバイダ、…と並び、届かなくなった段から `* * *` になります。どの部品の先で止まっているかが一目で分かります。

## まとめ

- 家の中はプライベートIP(`192.168.x.x`)、外はグローバルIP。ルーターが NAT で変換する
- 家の中の IP はルーターが DHCP で配る。もらえないと `169.254.x.x` になり、どこにも届かない
- ルーターは出入口(ゲートウェイ)。外向きのパケットは全部ここを通る
- `Network is unreachable`(自分がつながっていない)、`Destination Host Unreachable`(ルーターが返事しない)、`100% packet loss`(その先で消えた)を見分ける
