## つながったら、頼む

DNS で住所を引き、TCP でつながったら、ようやく「このページをください」と頼めます。この頼み方の決まりが **HTTP** です。ブラウザもサーバーも HTTP という共通の言葉で話すので、どのブラウザでもどのサーバーのページが見られます。

## リクエストとレスポンス

ブラウザが送る「頼みごと」が**リクエスト**です。中身はただの文字です。

```
GET /index.html HTTP/1.1
Host: example.com
```

`GET` は「取得したい」という動詞(**メソッド**)、`/index.html` が欲しいもの(**パス**)です。フォームの送信など、データを送るときは `POST` を使います。

サーバーの返事が**レスポンス**で、1行目に**状態コード**という3桁の番号が付きます。

```
HTTP/1.1 200 OK
Server: nginx/1.24.0
Content-Type: text/html; charset=utf-8

<!doctype html>...
```

1行目が結果、続く数行が**ヘッダー**(付帯情報)、空行のあとが本体(HTML)です。`Server: nginx` は、前に話した nginx がこのサーバーで応えていることを示しています。

ヘッダーだけ見たいときは `curl -I` です。

```sh
curl -I http://example.com/
```

## 状態コード

3桁の番号は、1桁目で大まかな意味が分かります。

| 番号 | 意味 | よく見るもの |
| --- | --- | --- |
| 2xx | 成功 | **200 OK** |
| 3xx | 別の場所へ(転送) | 301 Moved Permanently |
| 4xx | **頼んだ側**の間違い | **404 Not Found**、**403 Forbidden** |
| 5xx | **サーバー側**の失敗 | **500 Internal Server Error**、502、503 |

覚えておくべきは、4xx と 5xx の違いです。

- **404** は「そのページはない」。URL の打ち間違いや、消えたページ。頼んだ側が直す
- **403** は「見る権限がない」。ページはあるが入れない
- **500** は「サーバーのプログラムが失敗した」。頼み方は正しいので、サーバーを直すしかない

練習場では、`/admin` が 403、`/boom` が 500、それ以外の知らないパスが 404 を返すようにしてあります。

## 「つながらない」と「エラーが返る」は別物

ここまでのレッスンで見たエラーと、状態コードはまったく別の段階です。

```
Could not resolve host       ← 1. 名前が引けない(DNS)
Network is unreachable       ← 2. 自分がつながっていない
Connection timed out         ← 2. 相手まで届かない
Connection refused           ← 2. 相手のポートが閉じている
404 Not Found                ← 3. つながって、頼んで、「ない」と返事が来た
500 Internal Server Error    ← 3. つながって、頼んで、サーバーが失敗した
```

状態コードが返ってきたなら、**ネットワークは全部正常**です。DNS もルーターも回線もサーバーも動いていて、問題は「頼んだもの」か「サーバーのプログラム」にあります。404 が出ているのにケーブルを抜き差ししても直りません。

## HTTP と HTTPS

HTTP はただの文字なので、途中で誰かに読まれる可能性があります。これを暗号化したのが **HTTPS** で、前に話した**証明書**を使います。中身の話し方(GET、200、404)は同じで、外側に暗号の封筒をかぶせただけです。ポートは 80 ではなく 443 を使います。

## まとめ

- HTTP はブラウザとサーバーの共通の話し方。リクエストとレスポンスのやりとり
- リクエストは `GET /パス`、レスポンスは状態コード + ヘッダー + 本体
- 2xx 成功、3xx 転送、4xx 頼んだ側の間違い、5xx サーバー側の失敗
- 状態コードが返ったなら、ネットワークは正常。問題は別の所にある
