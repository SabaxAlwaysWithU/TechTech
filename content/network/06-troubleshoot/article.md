## 「ネットが使えない」を分解する

「ネットが使えない」と言われても、原因は7通り以上あります。片っ端から再起動するのではなく、**手前から順に1つずつ確かめる**のがコツです。ここまでのレッスンで、そのための道具は全部そろっています。

## 下から順に調べる

```
1. ip addr                自分は住所を持っているか
2. ping 192.168.1.1       ルーターまで届くか
3. ping 8.8.8.8           インターネットの向こうまで届くか
4. nslookup example.com   名前が引けるか
5. curl http://example.com/   ページが取れるか
```

どこかで失敗したら、**その手前の部品と、失敗したところの間**が怪しい、と絞り込めます。

| 失敗した段 | 出るエラー | 疑う部品 |
| --- | --- | --- |
| 1 | `169.254.x.x` になっている | IPアドレスの設定(DHCP) |
| 2 | `Network is unreachable` | ケーブル / Wi-Fi |
| 2 | `Destination Host Unreachable` | ルーター |
| 3 | `100% packet loss` | インターネット回線 |
| 4 | `connection timed out; no servers could be reached` | DNS サーバー |
| 5 | `Connection refused` | サーバーのポート |
| 5 | `Connection timed out` | Webサーバー |
| 5 | `404`、`500` | ネットワークは正常。ページかプログラム |

`ping 8.8.8.8` がポイントです。IPアドレスを直接使うので、DNS が死んでいても通ります。3が通って4が失敗すれば、DNS だけの問題だと確定します。

## traceroute で一気に見る

段階を1つずつ確かめる代わりに、`traceroute` で経路をまとめて見る方法もあります。

```sh
traceroute example.com
```

`* * *` になった段の直前までは正常です。ただし、名前を使うので最初に DNS が必要です。DNS が死んでいると、traceroute 自体が名前を引けずに止まります。そのときは `traceroute 93.184.216.34` のように IP で打ちます。

## 現実のトラブルとの対応

練習場の部品は、現実の困りごとにそのまま対応しています。

| 現実の症状 | 練習場の部品 |
| --- | --- |
| Wi-Fi のマークに × が付いている | ケーブル / Wi-Fi |
| Wi-Fi はつながっているのに「インターネットなし」 | IPアドレスの設定、またはインターネット回線 |
| ルーターのランプが全部消えている | ルーター |
| ルーターの「インターネット」ランプだけ赤い | インターネット回線 |
| LINE は届くのに、どのサイトも開けない | DNS |
| 1つのサイトだけ開けない | そのサイトの Webサーバーかポート |
| ページは出るが「404」 | ネットワークは正常 |

## 再起動はなぜ効くのか

「ルーターを再起動したら直った」はよくある話です。再起動すると、ルーターは回線をつなぎ直し、DHCP で IP を配り直し、DNS のキャッシュを消します。つまり、上の表の多くの部品を一度にリセットしています。

効くことは多いですが、原因が分からないままなので、また起きます。下から順に調べる手順を知っていれば、「回線側の問題なのでプロバイダに連絡しよう」「DNS だけなので設定を変えよう」と、正しい手が打てます。

## まとめ

- 「つながらない」は下から順に、ip addr → ping ルーター → ping 8.8.8.8 → nslookup → curl
- 失敗した段とエラーの文言で、壊れた部品が当てられる
- `ping 8.8.8.8` は DNS を使わない。DNS だけの故障の切り分けに使う
- 再起動は多くを一度にリセットする。効くが、原因は分からない
