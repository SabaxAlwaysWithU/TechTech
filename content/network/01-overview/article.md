## 手紙が届くまで

手紙を出すとき、あなたは宛先の住所を書いてポストに入れます。郵便局が集め、仕分けし、トラックや飛行機で運び、相手の家の郵便受けに入れます。あなたは「住所を書いて出す」だけで、途中の経路は考えません。

インターネットも同じです。ブラウザで `example.com` を開くとき、データは**パケット**という小さな封筒に分けられ、宛先の**IPアドレス**(住所)を付けて送り出されます。途中には、家の**ルーター**、プロバイダ、いくつもの中継点があり、最後に **Webサーバー**に届きます。返事も同じ道を戻ってきます。

## 登場する部品

練習場の図にある部品を、手前から順に見ていきます。

| 部品 | 役割 | 住所(IPアドレス) |
| --- | --- | --- |
| PC | あなたのパソコン。ブラウザが動いている | 192.168.1.10 |
| ケーブル / Wi-Fi | PC とルーターをつなぐ線(無線なら電波) | なし |
| ルーター | 家の中と外をつなぐ出入口。郵便局の窓口 | 192.168.1.1 |
| インターネット回線 | プロバイダを通って世界中につながる | (いろいろ) |
| DNSサーバー | 名前(`example.com`)を住所(IP)に変える電話帳 | 8.8.8.8 |
| Webサーバー | ページを持っていて、頼まれたら返す | 93.184.216.34 |

どれか1つでも壊れると、ページは見られません。ただし、**どこが壊れたかでエラーの出方が違います**。それを見分けられるようになるのが、この分野のゴールです。

## 1回のアクセスで起きること

ブラウザに `http://example.com/` と打って Enter を押したとき、裏ではこの順に進みます。

1. **名前を住所に変える**: `example.com` は人間用の名前なので、DNS サーバーに「住所は?」と聞き、`93.184.216.34` を教えてもらう
2. **道を確かめてつなぐ**: その住所に向けて、ルーター → プロバイダ → … と経路をたどり、サーバーと「話す準備」をする(TCP)
3. **ページを頼む**: 「`/` のページをください」と頼む(HTTP)
4. **返事をもらう**: サーバーが HTML を返し、ブラウザが画面に描く

1 で失敗すれば「名前が引けない」、2 で失敗すれば「つながらない」、3〜4 で失敗すれば「404」などの返事が来ます。失敗の種類が、どの段階で止まったかを教えてくれます。

## 自分の住所を見る

練習場のターミナルで、まず自分のIPアドレスを見てみましょう。

```sh
ip addr
```

`192.168.1.10` が自分、`gateway 192.168.1.1` が家のルーターです。Windows なら `ipconfig` と打つと同じものが見られます。

## 届くか確かめる: ping

`ping` は「そこにいますか?」と小さなパケットを送って、返事が来るかを見るコマンドです。

```sh
ping 192.168.1.1
```

`64 bytes from 192.168.1.1 ... time=0.9 ms` のような行が返れば、ルーターまでは届いています。`time` は往復にかかった時間で、家の中なら 1ms 以下、インターネットの向こうなら十数 ms です。

```sh
ping example.com
```

名前でも ping できます。このとき裏では DNS で住所を引いてから送っています。

## ページを取りに行く: curl

ブラウザの代わりにページを取りに行くのが `curl` です。

```sh
curl http://example.com/
```

HTML がそのまま表示されます。ブラウザはこれを画面に描いているだけです。

## まとめ

- データはパケットという封筒に分けられ、IPアドレス宛てに運ばれる
- 通り道は PC → ケーブル → ルーター → 回線 → (DNS) → Webサーバー
- 1回のアクセスは、名前を引く → つなぐ → 頼む → 返事、の4段階
- どの段階で失敗したかで、エラーの出方が変わる
