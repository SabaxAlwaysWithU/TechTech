## 店をどこに出すか

料理ができても、店がなければ客は来ません。Webアプリも、作ったプログラムを**インターネットにつながったコンピュータ**に置いて、動かし続ける必要があります。それが公開先(ホスティング)です。

「自分のパソコンで動けばいい」ではだめなのは、パソコンを閉じたらサイトが消えるからです。24時間動き続けるコンピュータを、どこかから借ります。

## 静的サイトの公開先

HTMLファイルを置くだけの静的サイトは、いちばん簡単で、ほぼ無料です。

| サービス | 特徴 |
| --- | --- |
| **GitHub Pages** | GitHub のリポジトリから直接公開。このサイトもこれ。学習とポートフォリオに最適 |
| **Netlify / Vercel / Cloudflare Pages** | push すると自動でビルドして公開。フォームやプレビュー機能もある。Vercel は Next.js の開発元 |

静的ホスティングは「ファイルを配る」ことに特化しているので、世界中の近い場所から配信され(CDN)、速くて落ちにくいです。サーバー側の処理は動きませんが、BaaS と組み合わせれば動的なアプリも作れます。

## サーバーを動かす公開先

バックエンドのプログラムを動かし続けるには、別の種類の場所が必要です。「どこまで自分で面倒を見るか」で3段階あります。

### PaaS: プログラムを渡せば動かしてくれる

**Render、Railway、Fly.io**(かつての Heroku)は、コードを push するだけで、OSやネットワークの設定なしにサーバーとDBを動かしてくれます。個人開発や小〜中規模のサービスには、まずこれです。無料枠はありますが、一定時間アクセスがないと眠る、などの制限があります。

### クラウド: 部品を自分で組み合わせる

**AWS、Google Cloud、Azure** は、サーバー、DB、ストレージ、ネットワークといった部品を、必要なだけ借りて組み合わせます。何でもできる代わりに、設定項目が多く、料金の仕組みも複雑です。会社のサービスや、大きく育ったアプリで使います。学生のうちは「存在と役割を知っている」で十分です。

### VPS: 1台まるごと借りる

**さくらのVPS、ConoHa** などは、仮想のコンピュータを1台借り、OSのインストールから全部自分でやります。OS分野で学んだ `ssh`、`chmod`、プロセス管理がそのまま必要になります。自由で安いですが、セキュリティ更新や障害対応も自分の仕事です。

### レンタルサーバー

PHP と MySQL が最初から動く共用サーバーで、WordPress や Laravel を置くのに向きます。Node.js や Python は動かないことが多いので、それ以外のバックエンドには使えません。

## 選び方

```
静的サイト ──────────────── GitHub Pages / Netlify / Vercel
バックエンドあり
 ├─ 個人、小〜中規模 ────── PaaS(Render / Railway / Fly.io)
 ├─ PHP(WordPress 等) ──── レンタルサーバー
 ├─ OSから学びたい、安く ── VPS
 └─ 会社、大規模 ────────── クラウド(AWS など)
```

## 公開に必要なその他のもの

- **ドメイン**: `example.com` のような名前。年に千円〜数千円で借りる。なくても公開はできる(`〜.github.io` などのサービスの名前になる)
- **HTTPS**: 通信の暗号化。今はどのサービスも自動で付けてくれる
- **環境変数**: DBのパスワードなど、コードに書いてはいけない値を公開先に設定する仕組み
- **Docker**: アプリと動作環境をまとめて1つの「箱」にする道具。PaaS やクラウドで「どこでも同じように動かす」ために使う。最初は不要だが、名前は覚えておく

## まとめ

- 静的サイトは GitHub Pages / Netlify / Vercel に無料で置ける
- バックエンドがあるなら、まず PaaS(Render / Railway / Fly.io)
- クラウドは何でもできるが設定が多い。VPS は全部自分でやる
- ドメインと HTTPS、環境変数は、公開のときに必ず出会う言葉
