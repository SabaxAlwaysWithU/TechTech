## 目的は「作ること」ではない

頼まれごとの本当の目的は「サイトを作ること」ではなく、「お店を知ってもらう」「商品を売る」といった**困りごとの解決**です。引っ越しでトラックを自分で作る人はいないように、よくある困りごとには出来上がったサービスがあります。**作らずに借りる**のも、立派な技術的判断です。

## どんなサービスがあるか

| 種類 | 代表例 | 向いていること |
| --- | --- | --- |
| ノーコードのサイト作成 | STUDIO、Wix、ペライチ | お店や会社の紹介サイト。見た目にこだわりたい |
| CMS | WordPress | ブログ、お知らせ、記事が増えていくサイト |
| ネットショップ作成 | Shopify、BASE | 商品を売る。決済、在庫、発送の管理 |
| フォームと表計算 | Google フォーム、スプレッドシート | 申し込み、アンケート、出欠を集める |
| ノーコードのアプリ作成 | kintone、Glide、Bubble | 社内の管理アプリ、簡単な予約や一覧 |

**ノーコード**は、画面の上で部品を並べて作る道具です。**CMS** は、管理画面から記事を書いて公開する仕組みで、WordPress は世界の Web サイトの4割ほどで使われていると言われます。

## サービスに任せられること

ネットショップを自分のコードで作ると、決めることと作るものが山ほどあります。

- 商品の一覧と詳細ページ、カート
- クレジットカードの決済(カードの番号を安全に扱う、厳しい決まりがある)
- 在庫の管理、注文の受付メール、発送の管理
- サーバーの管理、セキュリティの更新、バックアップ

Shopify や BASE は、これを全部用意してくれています。特に**決済**は、まちがえるとお金やカード情報に関わるので、実績のあるサービスに任せるのが安全です。

## 選ぶときの問い

1. **既存のサービスでできることか?** 紹介、ブログ、販売、申し込みなど、よくあることなら、まずサービスを探す
2. **誰が更新するか?** プログラミングをしない人(お店の人など)が自分で更新するなら、管理画面のあるサービスが向く
3. **お金はどちらが安いか?** サービスは月額や手数料が続く。コードで作るなら、作る人の時間と、直し続ける人の時間がかかる
4. **ほかにない仕組みか?** そのサービスの中心になる独自の仕組み(マッチングの方法、独自の計算など)があるなら、コードで作る

## 借りることの弱点

便利な反面、サービスには弱点もあります。

- **できることに上限がある**。サービスが用意していない機能は、基本的に作れない
- **引っ越しにくい**。作ったページやデータを、別のサービスにそのまま持っていけないことが多い(ロックイン)
- **料金が続く**。値上げされることもある。売り上げの何%という手数料は、売れるほど大きくなる
- **サービスが終わることがある**。終了や仕様の変更に合わせるしかない

最初はサービスで始めて、うまくいって独自の機能が必要になったら、コードで作り直す、という進め方もよくあります。

## 組み合わせる

全部をどちらかに決める必要はありません。

- 紹介サイトは STUDIO で作り、お問い合わせだけ Google フォームを埋め込む
- Shopify でお店を作り、見た目のテーマだけ HTML / CSS で直す
- 記事の管理だけをサービス(ヘッドレス CMS。microCMS など)に任せ、表示は Astro で作る

最後の例は、このサイトのような Astro の静的サイトと相性がよく、「書く人は管理画面、見た目はコード」と役割を分けられます。

## WordPress は「サービス」と「コード」の間

レッスン「公開先の種類」のパン屋さんの課題では、WordPress を4層に当てはめて考えました。WordPress は PHP で書かれたプログラムで、レンタルサーバーに置いて自分で動かすのが定番です。一方で、WordPress.com のように、サーバーの面倒まで見てくれるサービスもあります。

自分で置く場合は、本体やプラグインの**更新が自分の仕事**です。古いまま放っておくと、知られた弱点を突かれて乗っ取られることがあります。

## まとめ

- 目的は困りごとの解決。よくあることなら、作らずにサービスを借りるのも技術的な判断
- 紹介はノーコードのサイト作成、記事は CMS、販売はネットショップ作成、申し込みはフォーム、社内の管理はノーコードのアプリ
- 決済のように、まちがえると危ないものは、実績のあるサービスに任せる
- 弱点は、上限、引っ越しにくさ、続く料金、サービスの終了。独自の仕組みが中心ならコードで作る
