## レストランで考える

レストランには、客席(見える部分)、厨房(見えない部分)、食材庫、そして店舗そのもの(場所)があります。客は客席しか見ませんが、注文は厨房に届き、厨房は食材庫から材料を取って料理を返します。

Webアプリもこの4つでできています。

| 層 | レストランでいうと | Webアプリでは |
| --- | --- | --- |
| フロントエンド | 客席 | ブラウザに表示される画面。HTML / CSS / JavaScript |
| バックエンド | 厨房 | サーバーで動く処理。ログイン、保存、計算 |
| データベース | 食材庫 | データを保存しておく場所 |
| 公開先 | 店舗の土地と建物 | プログラムを置いて動かすコンピュータ |

これから6レッスンで、それぞれの層に「どんな種類の道具があり、どれをいつ選ぶか」を見ていきます。

## リクエストとレスポンス

ブラウザでURLを開くと、ブラウザは「このページをください」という**リクエスト**をサーバーに送ります。サーバーはHTMLを**レスポンス**として返し、ブラウザがそれを画面に描きます。

```
ブラウザ ──「/products を見せて」──→ サーバー
                                      │ 必要ならDBに問い合わせ
ブラウザ ←──  HTML(商品一覧)  ──── サーバー
```

ボタンを押して「保存」するときも同じで、ブラウザが「このデータを保存して」とリクエストし、サーバーがDBに書き込んで「保存しました」と返します。Webアプリのすべての動きは、この往復の繰り返しです。

## 静的サイトと動的サイト

ここで大事な分かれ目があります。

**静的サイト**は、あらかじめ作っておいたHTMLファイルをそのまま返すだけのサイトです。誰が見ても同じ内容で、サーバー側の処理がいりません。このサイトも静的サイトで、学習の記録はあなたのブラウザの中にだけ保存しています。

**動的サイト**は、リクエストのたびにサーバーがHTMLやデータを作って返すサイトです。ログインした人ごとに違う内容を出す、投稿を保存する、在庫を数える、といったことは動的サイトでないとできません。

| | 静的 | 動的 |
| --- | --- | --- |
| バックエンド | いらない | いる |
| データベース | たいてい いらない | たいてい いる |
| 公開 | 無料で簡単 | サーバーを動かし続ける必要がある |
| 例 | 紹介ページ、ブログ、ドキュメント | SNS、ネットショップ、予約システム |

「作りたいものは静的で済むか、動的が必要か」が、道具選びの最初の問いです。**ユーザーごとに違うデータを保存するなら動的**、そうでなければ静的で済むことが多いです。

## 言葉の整理

- **フレームワーク**: よくある作り方をまとめた「型」。これに沿って書くと、面倒な部分を省ける。Reactや Django など
- **ライブラリ**: 特定の機能だけを提供する部品。フレームワークより小さい
- **スタック**: 使う道具の組み合わせのこと。「React + Express + PostgreSQL」のように並べて言う
- **フルスタック**: フロントからバックまで一通りやること、またはそれができる人・道具

## まとめ

- Webアプリは、フロントエンド、バックエンド、データベース、公開先の4層
- ブラウザとサーバーはリクエストとレスポンスの往復で動く
- 静的サイトはHTMLを置くだけ、動的サイトはサーバーが毎回作る
- ユーザーごとのデータを保存するなら動的。最初に決める問いはこれ
