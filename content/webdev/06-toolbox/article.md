## 4層のまわりにある道具

フロント、バック、DB、公開先の4層を選んでも、それだけでは開発は始まりません。コードを管理し、部品を取り寄せ、変換し、確かめ、届ける道具が必要です。どのスタックを選んでも、ここはほぼ共通です。

## バージョン管理: Git と GitHub

**Git** はコードの変更履歴を記録する道具、**GitHub** はそれを置いて共有する場所です。「いつ、誰が、何を変えたか」が残り、壊れたら戻せ、複数人で同時に作業できます。このサイトも Git で管理し、GitHub に push すると公開されています。

Web開発では Git は空気のようなもので、使えないという選択肢がありません。最初に覚える道具です。

## パッケージ管理: npm、pip

他の人が作ったライブラリを取り寄せて使う仕組みです。Node.js では **npm**(`npm install react`)、Python では **pip**(`pip install django`)です。

取り寄せたものの一覧は `package.json` や `requirements.txt` に記録されます。この1枚があれば、別のパソコンでも同じ部品がそろいます。

## ビルド: Vite、TypeScript

書いたコードを、ブラウザやサーバーが実行できる形に変換する工程が**ビルド**です。

- **Vite**: フロントエンドのビルドの定番。開発中はすぐに画面に反映され、公開時は小さくまとめてくれる。Astro や SvelteKit の中でも使われている
- **TypeScript**: 型を付けた JavaScript を、普通の JavaScript に変換する

「`npm run build` を打つと `dist` フォルダができる」という流れは、ほとんどのフロントエンドで共通です。

## テスト

書いたコードが正しく動くかを、プログラムで自動的に確かめます。**Vitest / Jest**(JavaScript)、**pytest**(Python)などです。

テストがあると、あとから直したときに「他の場所が壊れていないか」を数秒で確認できます。このサイトの課題の模範解答も、自動で実行して確かめる仕組みが入っています。

## CI/CD: push したら自動で

**GitHub Actions** などで、「push されたらテストを動かし、通ったら公開する」を自動化します。CI(継続的インテグレーション)がテスト、CD(継続的デリバリー)が公開の自動化です。このサイトの公開も GitHub Actions がやっています。

## その他、名前を知っておく道具

| 道具 | 役割 |
| --- | --- |
| **ESLint / Prettier** | コードの書き方をそろえる、ミスを指摘する |
| **Docker** | アプリと環境をまとめて箱にする。「自分のPCでは動くのに」をなくす |
| **Postman / curl** | API を手で叩いて確かめる |
| **認証サービス**(Auth0、Clerk、Firebase Auth) | ログイン機能を借りる |
| **Stripe** | 決済を借りる |

## 定番の組み合わせ

最後に、よく見るスタックを5つ並べます。名前を見たときに「あの構成か」と分かれば十分です。

| 名前 | 構成 | 向いているもの |
| --- | --- | --- |
| 静的サイト | Astro + GitHub Pages | ブログ、ドキュメント、紹介サイト。このサイト |
| JAMstack | React / Next.js + BaaS(Supabase) + Vercel | 個人開発のWebアプリ。サーバーを書かない |
| フルスタック JS | Next.js + Prisma + PostgreSQL + Vercel / Railway | 本格的なアプリを JavaScript だけで |
| モノリス | Rails / Django / Laravel + PostgreSQL + PaaS | 会員制サービスを一式、速く |
| 分離構成 | React(Vercel)+ FastAPI / Express(PaaS)+ PostgreSQL | フロントとバックを別チームで、またはスマホアプリと共用 |

## 最初の一歩はどれか

ここまで名前をたくさん出しましたが、全部を覚える必要はありません。

1. まず **静的サイト**(HTML / CSS、そして Astro)で1つ公開する。このサイトで学んだことで足りる
2. 次に **JavaScript + BaaS** でログインと保存のあるアプリを1つ作る。サーバーを書かずに動的サイトを経験できる
3. そのあと **Node.js か Python でバックエンド** を自分で書く。SQL 分野の知識がここでつながる

道具は、必要になったときに1つずつ足せば間に合います。

## まとめ

- Git / GitHub、npm、ビルド、テスト、CI/CD はどのスタックでも共通の土台
- 定番の組み合わせを5つ知っておくと、人の構成を見て理解できる
- 最初は静的サイト → BaaS → 自分でバックエンド、の順で1つずつ
