## 公開してからが本番

VPS(仮想サーバー)を借りてアプリを置いただけでは、まだ安心して使えるサイトにはなりません。お店にたとえると、建物(サーバー)と商品(アプリ)のほかに、受付、防犯の鍵、倒れた店員を起こす仕組み、遠くのお客さんのための支店が要ります。このレッスンでは、この**サーバーの裏側**の4つの役を見ます。

通信の細かい中身はネットワーク分野で扱ったので、ここでは「何を選ぶか」に絞ります。

## 1. 入口: Web サーバー

ブラウザからの接続を最初に受けるのが **Web サーバー**(nginx、Apache、Caddy)です。主な仕事は3つです。

- **静的なファイルを返す**: 画像や CSS は、アプリを通さずにそのまま返すほうが速い
- **取り次ぐ**(リバースプロキシ): `/api/` などの、アプリが答えるべき問い合わせを、後ろの Django や Express に渡す
- **HTTPS の暗号をほどく**: 証明書を持ち、暗号化された通信をここで受ける

| | 特徴 |
| --- | --- |
| nginx | 速くて軽い定番。リバースプロキシの設定例がいちばん多い |
| Apache | 古くからの定番。レンタルサーバーで多い |
| Caddy | 設定が短く、証明書を自動で取ってくれる |

## 2. 鍵: HTTPS の証明書

公開するサイトは、すべて HTTPS にするのが今の当たり前です。自分のサーバーなら、無料の **Let's Encrypt** が定番です。有効期限が90日と短いので、**自動で更新する設定**(certbot など)を必ず入れます。更新を忘れて期限が切れると、ネットワーク分野で見た `certificate has expired` のエラーになり、誰もサイトを見られなくなります。

会社の決まりで、会社の実在確認まで含んだ**有料の証明書**を使うこともあります。

## 3. 動かし続ける: プロセスの管理

ターミナルで `npm start` や `python manage.py runserver` を打てば、アプリは動きます。でも、そのままでは:

- ターミナルを閉じたり、ログアウトしたりすると止まる
- サーバーが再起動すると、止まったまま
- エラーで落ちても、誰も起こさない

そこで、アプリを「サービス」として見張ってもらいます。

- **systemd**: Linux 分野で使った `systemctl` の仕組みです。サーバーの起動時に自動で始め、落ちたら起こし直す設定ができます
- **Docker**: アプリと、動くのに必要なもの(Python の版、ライブラリなど)を「コンテナ」という箱にまとめます。どこでも同じ箱が同じように動き、再起動の決まりも書けます

## 4. 支店: CDN

サーバーが東京にあると、ヨーロッパの利用者には通信が地球を半周して届きます。SNS で話題になると、1台では返しきれなくなります。**CDN**(コンテンツ配信ネットワーク)は、世界中のサーバーに画像やページのコピーを置き、利用者に近いところから返す仕組みです(Cloudflare など)。本体への問い合わせも減ります。

利用者が国内の決まった人たちで、数も多くなければ、CDN なしでも十分です。

## PaaS が肩代わりしているもの

ここまでの4つを、全部自分で用意するのは大変です。公開先の種類によって、誰がやるかが変わります。

| | VPS | PaaS(Render など) | 静的ホスティング(GitHub Pages など) |
| --- | --- | --- | --- |
| 入口 | 自分で置く | サービス | サービス |
| 証明書 | 自分で(自動更新の設定も) | サービス | サービス |
| 動かし続ける | 自分で(systemd / Docker) | サービス | 不要(ファイルだけ) |
| CDN | 必要なら自分で | 必要なら | 最初から含まれる |

PaaS が VPS より高めでも選ばれるのは、この裏側の手間をまとめて引き受けてくれるからです。逆に VPS は、全部自分で決められる自由と、全部自分の責任、の両方を持っています。

## ほかにもある裏側の仕事

- **環境変数**: パスワードや秘密の鍵はコードに書かず、サーバーの設定に置く
- **ログ、バックアップ、監視**: 何が起きたかを記録し、データの写しを取り、止まったら知らせてもらう

## まとめ

- 入口の Web サーバー(nginx など)は、ファイルを返し、アプリに取り次ぎ、HTTPS を受ける
- 証明書は Let's Encrypt が定番。自動更新を必ず設定する
- アプリは systemd や Docker で見張り、落ちたら起こし、再起動しても動くようにする。手で起動したままにしない
- 遠くの利用者や急なアクセスには CDN
- PaaS や静的ホスティングは、これらの多くを肩代わりしてくれる。VPS は全部自分で決め、全部自分で面倒を見る
