## 今日の相談会

あなたは、Web アプリの作り方を相談される係です。今日は4組の相談があります。

1. 地域のお祭りの告知ページを、1日だけ公開したい
2. 美容室の予約システムを、Python が得意な2人で作り、何年も使いたい
3. スマホゲームのランキングを、とにかく速く返したい
4. 会社の在庫管理を、Java が得意なチームで作る。会社の決まりで AWS を使う

今日の相談会では、どの相談もコードを書いて作ると決まっています(作らずにサービスを借りる選択肢は、レッスン「コードを書かない選択肢」で見ました)。

練習場の4つの課題が、この4組です。それぞれ、4つの層(フロントエンド、バックエンド、データベース、公開先)を選んで「判定」を押します。選んだ理由や、合わない選択肢がなぜ合わないかも表示されます。

## 選ぶときの考え方

これまでのレッスンで見てきた問いを、上から順に当てはめます。

1. **保存やログインはいるか?** いらなければ、バックエンドもデータベースも「なし」で、静的サイトとして無料で公開できます
2. **誰が作り、誰が保守するか?** チームが得意な言語の枠組みを選ぶのが、いちばん失敗しにくい選び方です
3. **データはどんな形で、どう使うか?** 表で管理する大事なデータなら RDB(PostgreSQL / MySQL)。一時的で、とにかく速さが大事なデータなら Redis
4. **どこで動かすか?** 静的ならホスティングサービス、サーバー側のプログラムがあるなら PaaS かクラウド。会社の決まりがあれば、それに従います

## 正解は1つではない

多くの依頼で、正解になる選択肢は複数あります。たとえば「よく動く画面」なら React でも Vue でもかまいません。判定では、要件を満たす選択肢ならどれでも正解にしています。

大事なのは、「なぜそれを選んだか」を言えることです。判定のあとに出る説明を読んで、自分の理由と比べてみてください。理由が言える選び方ができれば、これからどんな技術が出てきても、同じ考え方で選べます。
