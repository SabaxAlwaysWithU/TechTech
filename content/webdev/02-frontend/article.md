## 画面の作り方は1つではない

HTML / CSS / JavaScript だけでもWebページは作れます。HTML/CSS分野で作ったのがまさにそれです。では、なぜ React や Vue といった道具があるのでしょう。

ページが大きくなると、「ボタンを押したら一覧が更新され、件数の表示も変わり、空ならメッセージを出す」のような**画面の状態の管理**が急に難しくなります。フロントエンドのフレームワークは、この難しさを引き受けてくれる道具です。

## 3つの段階

| 段階 | 道具 | 向いているもの |
| --- | --- | --- |
| 素の HTML / CSS / JS | なし | 数ページの紹介サイト、学習 |
| UIライブラリ | React、Vue、Svelte | 画面がよく動くアプリ |
| メタフレームワーク | Next.js、Nuxt、Astro | ページ分け・公開まで含めた本格的なサイト |

下に行くほどできることは増えますが、覚えることも増えます。「必要になったら次の段階へ」が基本です。

## UIライブラリ: React、Vue、Svelte

3つとも、画面を**コンポーネント**という部品に分けて組み立てる考え方です。「商品カード」という部品を1回作れば、商品が100個でも同じ部品を100回使えます。データが変わると、画面の該当部分だけが自動で描き直されます。

- **React**: 最も使われている。情報も求人も多い。書き方はJavaScriptそのものに近く、最初はとっつきにくい
- **Vue**: HTMLに近い書き方で、学びやすい。日本で人気
- **Svelte**: 書く量がいちばん少ない。ビルド後のコードが軽い

どれも「できること」に大差はありません。迷ったら、情報量の多さで React、学びやすさで Vue を選べば間違いありません。

## メタフレームワーク: Next.js、Nuxt、Astro

React や Vue は「画面の部品」を作る道具で、「ページをURLごとに分ける」「サーバー側で先にHTMLを作る」「公開する」までは面倒を見てくれません。それを足したものが**メタフレームワーク**です。

- **Next.js**(React)、**Nuxt**(Vue): ログイン、データ更新、サーバー側の処理まで1つの枠組みで書ける。本格的なアプリの定番
- **Astro**: 「読むサイト」に特化。ビルド時に静的HTMLを作るので速く、JavaScriptをほとんど送らない。ブログ、ドキュメント、このサイトのような学習サイト向け

## どう選ぶか

```
画面はほとんど動かない(紹介、記事)
 ├─ 数ページ ────────── 素のHTML
 └─ 記事が多い ──────── Astro

画面がよく動く(入力、一覧の更新、チャット)
 ├─ 1画面のツール ───── React / Vue / Svelte
 └─ ページ複数 + ログイン ─ Next.js / Nuxt
```

「動く」とは、ページを読み込み直さずに画面の一部が変わることです。買い物かごの件数が増える、入力しながら候補が出る、といった動きです。

## 補足: TypeScript

JavaScript に「型」を足した **TypeScript** は、今のフロントエンド開発ではほぼ標準です。変数に何が入るかを書いておくことで、書き間違いを実行前に見つけられます。どのフレームワークも TypeScript で書けます。JavaScript 分野を終えたら、次に学ぶ候補です。

## まとめ

- 素のHTML → UIライブラリ → メタフレームワークの3段階。必要になったら次へ
- React / Vue / Svelte は画面を部品で組む道具。できることに大差はない
- Next.js / Nuxt は本格的なアプリ向け、Astro は読むサイト向け
- 「画面がどれだけ動くか」で選ぶ
