## 頼まれごと

ネットショップの注文処理を担当することになりました。注文は1日に何万件も来るので、遅い手順では間に合いません。お願いは5つです。

1. 注文番号から、その注文をすぐ探す
2. 注文したお客さんの一覧を、重なりなしで作る
3. 商品ごとに、注文された数を合計する
4. 売れた数の上位の商品を出す
5. 在庫を見ながら、来た順に出荷する

練習場の5つの課題が、この5つです。どれも関数を作る課題で、関数を呼んだ結果で判定します。

## 注文のデータ

注文1件が1つの辞書で、番号の小さい順(来た順)に並んでいます。

```python
orders = [
    {"id": 1001, "customer": "山田", "product": "マウス", "qty": 2},
    {"id": 1002, "customer": "佐藤", "product": "モニター", "qty": 1},
    {"id": 1003, "customer": "山田", "product": "キーボード", "qty": 1},
]
print(orders[1]["product"])
```

## 使う知識

| 頼まれごと | 使うもの | 計算量 | レッスン |
| --- | --- | --- | --- |
| 1 番号で探す | 二分探索 | O(log n) | 二分探索 |
| 2 お客さんの一覧 | 集合で「もう入れたか」 | O(n) | 辞書と集合で速くする |
| 3 商品ごとの数 | 辞書で数える | O(n) | 辞書と集合で速くする |
| 4 上位の商品 | sorted の key | O(n log n) | 速い並べ替え |
| 5 出荷 | キュー(deque) | O(n) | スタックとキュー |

## 遅い書き方に気をつける

どの課題も、手早く書くと O(n²) になってしまう落とし穴があります。

- 一覧を作るときに `if name not in names:`(リストの `in`)を使うと、全体が O(n²) になる → 集合で調べる
- 番号で探すときに、毎回リストを前から探すと、1回 O(n) → 番号の順に並んでいるので二分探索

判定では、大きなデータでも試します。正しい答えでも、時間内(5秒)に終わらないと不正解になります。

## 詰まったら

- まず小さなデータで `print` して、思ったとおりに動くか確かめる
- 「何度も探す」「すでにあるか調べる」が出てきたら、集合か辞書を使えないか考える
- 並んでいるデータを探すなら、二分探索を思い出す
