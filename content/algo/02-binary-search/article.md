## 数当てゲーム

「1〜100 のどれかを当てて。外れたら、もっと大きいか小さいかだけ教えるよ」というゲームで、1, 2, 3 … と順に言う人はいません。まず「50」と言い、「もっと大きい」なら次は「75」…と、**残りの真ん中**を言っていきます。そうすれば、どんな数でも7回以内に当てられます。

この方法を、並んでいるデータを探すのに使ったのが**二分探索**です。

## 真ん中を見て、半分を捨てる

二分探索は、データが**小さい順に並んでいる**ときだけ使えます。

1. 探す範囲の真ん中の値を見る
2. 探している値と同じなら、見つかった
3. 探している値のほうが大きければ、左半分を捨てて、右半分だけを探す(小さければ逆)
4. 範囲がなくなったら、見つからない

```python
def binary_search(items, target):
    low = 0
    high = len(items) - 1
    while low <= high:
        mid = (low + high) // 2
        if items[mid] == target:
            return mid
        elif items[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

prices = [800, 1800, 2500, 4200, 6800, 9800, 12000, 32000]
print(binary_search(prices, 6800))
print(binary_search(prices, 5000))
```

`low` と `high` が、まだ探す範囲の両はしの番号です。`//` は割り算の答えの整数部分(切り捨て)です。

## どれくらい速いのか

1回比べるたびに、探す範囲が**半分**になります。

| データの数 | 二分探索で比べる回数(最大) | 線形探索 |
| --- | --- | --- |
| 100 | 7 | 100 |
| 1,000 | 10 | 1,000 |
| 100万 | 20 | 100万 |
| 10億 | 30 | 10億 |

データが2倍になっても、比べる回数は1回しか増えません。「2を何回掛けたら n になるか」の回数(対数、log)なので、計算量は **O(log n)** です。10億件でも30回で見つかる、驚くほど速い方法です。

## 並べる手間との引き換え

二分探索の弱点は、**データが並んでいないと使えない**ことです。並べる手間(次のレッスン)がかかるので、1回しか探さないなら線形探索で十分です。何度も探すデータは、一度並べておけば、そのあとは毎回速く探せます。

データベースのインデックス(SQL の分野の「その先」)も、中では値を並べておいて、二分探索に似た方法で一気に探しています。辞書や電話帳があいうえお順なのも、同じ理由です。

## まとめ

- 二分探索は、並んだデータの真ん中を見て、半分ずつ捨てていく
- 1回ごとに範囲が半分になるので O(log n)。10億件でも約30回
- 使えるのは、データが並んでいるときだけ。何度も探すなら、先に並べておく価値がある
- データベースのインデックスも同じ考え方
