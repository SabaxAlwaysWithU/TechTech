## リストの in は遅い

`x in リスト` は、中で線形探索をしています(O(n))。1回なら気になりませんが、**ループの中で何度も**使うと、全体が O(n²) になってしまいます。

```python
def has_duplicate_slow(items):
    for i in range(len(items)):
        if items[i] in items[i + 1:]:
            return True
    return False

print(has_duplicate_slow([3, 1, 4, 1, 5]))
```

「同じ値が2回出てくるか」を調べるこのコードは、1つずつ、残りの全部と比べています。1万件で約5,000万回の比べっこです。

## 辞書と集合は、一発で引ける

Python の**辞書**(dict)と**集合**(set)は、`in` や `[キー]` での検索が、データがいくつあってもほぼ一瞬(**O(1)**)で終わります。

その秘密が**ハッシュ**です。キーから「しまう棚の番号」を計算で決めておき、探すときも同じ計算で棚の番号を出して、そこだけを見ます。図書館で、本の分類番号から棚が一発でわかるのと同じです。全部の棚を端から見る必要がありません。

```python
def has_duplicate(items):
    seen = set()
    for x in items:
        if x in seen:
            return True
        seen.add(x)
    return False

print(has_duplicate([3, 1, 4, 1, 5]))
print(has_duplicate([3, 1, 4]))
```

「今までに見たもの」を集合に入れておき、`in` で一発で確かめます。1回だけ前から見ればよいので、全体で **O(n)** になりました。1万件なら1万回ほどで済みます。

## 2つの数の和

もう1つ、有名な例です。「リストの中から、足すとちょうど `target` になる2つの数を探す」問題を考えます。

すべての組み合わせを試すと O(n²) です。辞書を使うと、こう考えられます。

- 前から1つずつ見ていき、「相手に必要な数」(`target - x`)が、**今までに見た数の中にあるか**を辞書で確かめる
- なければ、今の数を辞書に入れて先へ進む

```python
def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:
            return [seen[need], i]
        seen[x] = i
    return None

print(two_sum([2500, 6800, 1800, 4200], 6000))
```

辞書には「値 → 番号」を入れているので、見つかったら相手の番号もすぐわかります。

## ふつうの言葉にすると

- 「**何度も探す**なら、リストではなく集合か辞書に入れておく」
- 「**数える**なら、辞書(や Counter)」(Python の分野の「辞書」「標準ライブラリ」)

この2つを覚えておくだけで、多くのプログラムが何百倍も速くなります。データベースのインデックスにも、並べておく方法(二分探索型)と、このハッシュを使う方法があります。

## まとめ

- リストの `in` は O(n)。ループの中で使うと全体が O(n²) になる
- 辞書と集合はハッシュで棚の番号を計算するので、`in` も検索も O(1)
- 「今までに見たもの」を集合や辞書に入れておくと、O(n²) を O(n) にできる
- 何度も探すなら集合か辞書。数えるなら辞書
