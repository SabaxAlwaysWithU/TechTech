## 2進数の小数

10進数の小数は、小数点より右の桁の重みが 1/10、1/100、1/1000 … でした。2進数では、**1/2、1/4、1/8、1/16 …** になります。

```text
重み   4   2   1 . 1/2 1/4 1/8 1/16
       0   1   0 .  1   1   0   0     → 2 + 1/2 + 1/4 = 2.75
```

練習場では、ビットの真ん中に小数点のある並びで、小数を作れます。

## 0.1 は、ぴったり表せない

2.75 や 0.5 は、1/2 や 1/4 の組み合わせでぴったり作れます。では 0.1 はどうでしょう。

0.1 を 1/2、1/4、1/8 … の足し算で作ろうとすると、**どこまで行っても終わりません**。10進数で 1/3 が 0.3333… と無限に続くのと同じで、2進数では 0.1 が `0.000110011001100…` と無限に続きます。

コンピュータのビットの数には限りがあるので、途中で打ち切ります。だから、コンピュータの中の 0.1 は、**0.1 にとても近いけれど、ほんの少しずれた数**です。

## 0.1 + 0.2 は 0.3 にならない

少しずつずれた数を足すと、ずれも足されます。

```text
>>> 0.1 + 0.2              (Python。JavaScript でも同じ)
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False
```

バグではなく、ほとんどのプログラミング言語が使っている **浮動小数点数**(IEEE 754 という決まり)の性質です。Python の `float` も、JavaScript の数も、C の `double` も同じ結果になります。

浮動小数点数は、「1.0101 × 2の3乗」のように、**数字の並びと、小数点の位置(何乗か)を分けて**持つ仕組みです。小数点の位置を動かせる(浮動する)ので、とても大きな数もとても小さな数も、同じ64ビットで表せます。その代わり、けたの数には限りがあり、多くの小数はぴったりには表せません。

## どう付き合うか

- **お金は小数で計算しない**。1.10 ドルは 110 セントのように、いちばん小さい単位の**整数**で持つ。SQL の分野の値段が整数(円)だったのもこのため
- **小数を == で比べない**。差がとても小さければ同じとみなす(`abs(a - b) < 0.000001`)
- **表示のときに丸める**。`printf("%.2f")` や Python の `round` で、見せるけたを決める
- ぴったりの小数が必要なら、Python の `decimal` のような専用の道具を使う

## まとめ

- 2進数の小数は、1/2、1/4、1/8 … の重みを足して作る
- 0.1 は2進数では無限に続くので、コンピュータの中ではほんの少しずれている
- そのため 0.1 + 0.2 は 0.30000000000000004 になる。どの言語でも同じ(浮動小数点数の性質)
- お金は整数で持つ。小数は == で比べず、表示のときに丸める
