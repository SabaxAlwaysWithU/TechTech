## 電源ボタンの向こう側

電源を押してから画面が出るまでの数十秒、パソコンの中では順番にバトンが渡されています。誰が最初に動き、どこでOSが登場するのかを知ると、「起動しない」ときに何が起きているかが想像できるようになります。

## 起動の流れ

```
電源ON
 ↓
ファームウェア(UEFI / BIOS)
   部品の点検。どのディスクから起動するか決める
 ↓
ブートローダー
   ディスクからカーネルを読み込んでメモリに載せる
 ↓
カーネル
   メモリ、CPU、装置を初期化。最初のプロセス(init、PID 1)を起動
 ↓
init とサービス
   ネットワーク、ログ、画面表示などの裏方プロセスを順に起動
 ↓
ログイン画面
   ユーザー名とパスワードを確認して、その人の環境を用意する
```

ファームウェアはマザーボードに焼き込まれた小さなプログラムで、OSが読み込まれる前に動く唯一のものです。「起動するディスクの順番」を設定する画面(UEFI設定)は、ここの機能です。

ログインすると、ホームディレクトリが用意され、設定が読み込まれ、デスクトップやターミナルが使える状態になります。

## シェル: コマンドを受け取る係

ターミナルに `ls` と打つと、何が `ls` を実行しているのでしょう。それは**シェル**というプログラムです。

シェルは、打った文字を読み取り、コマンドの名前と引数に分け、該当するプログラムを探して起動し、結果を画面に出します。ターミナルは「文字を表示する窓」、シェルは「その中で命令を解釈する係」です。Linux で一般的なシェルは `bash` で、`ps` の一覧にも載っています。

OSの核(カーネル)を包む「殻(shell)」だから、シェルと呼びます。

## 環境変数

シェルは、動作に使う設定を**環境変数**として持っています。`env` で一覧が見られます。

```sh
env
```

| 変数 | 意味 |
| --- | --- |
| `HOME` | ホームディレクトリの場所 |
| `USER` | ログインしているユーザー名 |
| `PATH` | コマンドを探す場所の一覧 |
| `SHELL` | 使っているシェル |

変数の値は `$名前` で取り出せます。`echo` は文字を表示するコマンドなので、組み合わせると値が見られます。

```sh
echo $HOME
```

## PATH: コマンドはどこにある?

`ls` と打ったとき、シェルは `/bin/ls` というファイルを見つけて実行しています。どこを探すかを決めているのが `PATH` です。

```sh
echo $PATH
```

`/usr/bin:/bin` のように、ディレクトリが `:` で区切って並んでいます。シェルは左から順に探し、最初に見つかったものを実行します。あるコマンドがどこにあるかは `which` で分かります。

```sh
which ls
which python3
```

「コマンドが見つかりません」と言われるときは、そのプログラムが入っていないか、入っていても `PATH` のディレクトリにない、のどちらかです。プログラミングの環境構築で何度も出会うエラーなので、仕組みを覚えておくと困りません。

## 出力をファイルに保存する

`>` を使うと、コマンドの出力を画面ではなくファイルに書き込めます。

```sh
echo "今日やること" > notes/memo.txt
cat notes/memo.txt
```

`>` は上書き、`>>` は末尾に追加です。コマンドの結果を記録しておきたいときに使います。

## まとめ

- 起動はファームウェア → ブートローダー → カーネル → init → ログインの順
- シェルは打ったコマンドを解釈して実行する係。ターミナルはその窓
- 環境変数は `env` で一覧、`$名前` で取り出す
- `PATH` はコマンドを探す場所。`which` でどこにあるか分かる
