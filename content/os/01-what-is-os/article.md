## ビルの管理人

大きなビルを思い浮かべてください。テナント(会社)はたくさん入っていますが、電気、水道、エレベーター、鍵の管理をテナントが自分でやることはありません。管理人がまとめて面倒を見ていて、テナントは「3階に行きたい」「電気をつけたい」と頼むだけです。

パソコンでは、この管理人が **OS**(オペレーティングシステム)です。ビルがハードウェア(CPU、メモリ、ディスク、画面、キーボード)、テナントがアプリ(ブラウザ、ゲーム、エディタ)にあたります。

## OSがやっていること

アプリは、ハードウェアを直接さわりません。「このファイルを開いて」「画面にこの文字を出して」とOSに頼み、OSがハードウェアを動かします。OSの仕事は大きく4つです。

| 仕事 | 内容 |
| --- | --- |
| プロセスの管理 | どのアプリをいつ動かすか決める。たくさんのアプリが同時に動いているように見せる |
| メモリの管理 | アプリごとに使える場所を割り当て、他のアプリの場所をさわれないようにする |
| ファイルの管理 | ディスクの中のデータを「ファイル」と「フォルダ」の形で扱えるようにする |
| 装置の管理 | キーボード、マウス、画面、ネットワークなどとの通信を引き受ける |

どのアプリも同じ方法でOSに頼めるので、アプリを作る人はハードウェアの細かい違いを気にしなくて済みます。これがOSのいちばん大きな価値です。

## カーネル

OSの中心部分を**カーネル**と言います。ハードウェアに直接触れるのはカーネルだけで、アプリはカーネルに頼む形でしか動けません。そのおかげで、1つのアプリが暴走しても、他のアプリやOS全体を巻き込みにくくなっています。

カーネルの周りには、画面の見た目(デスクトップ)、設定画面、標準アプリなど、たくさんの部品が乗っています。普段「OS」と呼んでいるのは、これらを全部まとめたものです。

## 主なOS

| OS | 主な使われ方 |
| --- | --- |
| Windows | 家庭や会社のパソコン |
| macOS | Appleのパソコン |
| Linux | サーバー、開発、組み込み機器。無料で中身が公開されている |
| Android | スマートフォン。中身はLinux |
| iOS | iPhone。macOSと親戚 |

見た目や操作は違いますが、やっていることは同じです。このレッスンでは **Linux** の流儀で学びます。サーバーやプログラミングの現場で最も多く使われていて、仕組みが見えやすいからです。

## ターミナルで触る

OSに頼みごとをする方法は2つあります。マウスで操作する **GUI**(画面)と、文字で命令を打つ **CLI**(コマンドライン)です。

CLIで命令を打つ画面が**ターミナル**です。この分野の練習場は、ブラウザの中で動く練習用のターミナルです。最初の命令を打ってみましょう。

```sh
whoami
```

「今ログインしているユーザーは誰か」を答えてくれます。次はOSの名前です。

```sh
uname
```

`Linux` と返ってくるはずです。コマンドは「命令の名前」を打って Enter、が基本です。分からなくなったら `help` と打てば一覧が出ます。

## まとめ

- OSは、ハードウェアとアプリの間に立つ管理人
- 仕事はプロセス、メモリ、ファイル、装置の管理
- 中心部分がカーネル。ハードウェアをさわるのはカーネルだけ
- OSへの頼み方には GUI と CLI がある。CLI を使う画面がターミナル
