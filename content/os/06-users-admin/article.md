## 鍵の種類

アパートには、各部屋の鍵と、管理人が持つマスターキーがあります。住人は自分の部屋だけ、管理人は全部屋に入れます。便利ですが、マスターキーをなくすと全部屋が危険にさらされます。

OSにも同じ区別があります。普段使う**一般ユーザー**と、何でもできる**管理者**です。

## ユーザー

OSは「誰が操作しているか」を常に把握しています。ファイルには持ち主がいて、プロセスにも動かしている人がいます。レッスン4の権限は、この「誰か」を前提にした仕組みでした。

登録されているユーザーは `/etc/passwd` に書いてあります。

```sh
cat /etc/passwd
```

1行が1ユーザーで、名前、ID番号、ホームディレクトリ、使うシェルが `:` 区切りで並んでいます。名前のわりに、パスワードはここには書いてありません(昔は書いてあった名残です)。

## root: 何でもできるユーザー

管理者ユーザーの名前は **root** です。権限の制限を一切受けず、どのファイルも読み書きでき、誰のプロセスも止められ、OSの設定を変えられます。

強力なぶん危険です。`rm` を1回打ち間違えるだけでOSを壊せますし、root で動かしたアプリが悪意を持っていれば、パソコンを丸ごと乗っ取られます。だから普段は一般ユーザーで作業し、必要なときだけ管理者の力を借ります。

## sudo: 一時的に管理者になる

一般ユーザーが、1つのコマンドだけ root として実行する仕組みが `sudo` です。

```sh
cat /etc/shadow
sudo cat /etc/shadow
```

1行目は「許可がありません」と断られますが、`sudo` を付けると読めます。`/etc/shadow` はパスワード(を暗号化したもの)が入っているファイルで、root 以外は読めないようになっています。

本物のOSでは、`sudo` を打つと自分のパスワードを聞かれます。「本当にあなたですか」という確認です。Windows で「変更を許可しますか?」のダイアログが出るのも同じ仕組みです。

`sudo` が必要になる場面は、ソフトのインストール、システム設定の変更、他のユーザーのプロセスの停止などです。逆に言えば、普段の作業で `sudo` が要ることはほとんどありません。「`sudo` を付けたら動いた」で済ませず、なぜ権限が必要だったのかを考える癖をつけてください。

## ログ: OSの日記

OSや裏方のプロセスは、起きたことを**ログ**に記録しています。何かおかしいときの最初の手がかりです。

```sh
cat /var/log/system.log
```

時刻、どの部品が、何をしたかが1行ずつ並びます。`warning` や `error` と書かれた行を探すと、問題の原因に近づけます。レッスン3で止めた暴走プロセスも、ログに痕跡が残っています。

## 更新とセキュリティ

OSには、日々見つかる不具合や弱点を直す**更新**が配られます。更新を止めていると、知られた弱点がそのまま残り、攻撃に使われます。「更新は面倒」ではなく「鍵の交換」だと考えてください。

セキュリティの基本は、この分野で学んだ仕組みの組み合わせです。

- 権限: 必要な人だけが、必要なファイルを触れる
- ユーザーの分離: 普段は一般ユーザー。管理者は必要なときだけ
- プロセスの分離: 1つのアプリが他を壊せない
- ログ: 何が起きたかあとから追える
- 更新: 弱点を塞ぎ続ける

## まとめ

- ユーザーは `/etc/passwd` に登録されている。OSは常に「誰か」を把握している
- root は何でもできる管理者。普段は使わない
- `sudo コマンド` で、そのコマンドだけ root として実行する
- ログは `/var/log` にある。問題の手がかりはまずここ
- 更新は弱点を塞ぐ作業。止めない
