## 料理人は1人、注文はたくさん

厨房に料理人が1人しかいないのに、注文は同時に10件入ります。料理人は「Aの肉を焼いている間にBのスープを温め、Cの盛り付けをして、Aに戻る」と細かく切り替えながら全部を進めます。客からは、10品が同時に作られているように見えます。

CPUとOSの関係も同じです。CPUは一度に1つのことしかできませんが、OSが切り替えを高速に繰り返すので、ブラウザも音楽も、同時に動いているように見えます。

## プログラムとプロセス

ディスクに置いてあるファイルとしてのアプリが**プログラム**、それを起動して動いている状態が**プロセス**です。レシピ(プログラム)と、今まさに作っている料理(プロセス)の違いです。同じプログラムを2回起動すれば、プロセスは2つできます。

OSはプロセスごとに番号を付けて管理します。これが **PID**(プロセスID)です。

## プロセスを見る: ps

動いているプロセスの一覧を見るコマンドが `ps` です。

```sh
ps
```

| 列 | 意味 |
| --- | --- |
| PID | プロセスの番号 |
| USER | 誰が動かしているか |
| %CPU | CPUをどれだけ使っているか |
| MEM | 使っているメモリ(MB) |
| COMMAND | プログラムの名前 |

PID が 1 の `init` は、OSが起動して最初に動くプロセスで、他のすべてのプロセスの親です。

## 止める: kill

応答しなくなったアプリを強制終了するのが `kill` です。PID を指定します。

```sh
kill 777
```

名前が「kill(殺す)」なので物騒ですが、本来は「プロセスに合図を送る」コマンドです。合図を受け取ったプロセスは、普通は後片付けをして終了します。

自分のプロセスしか止められません。他のユーザーやOS自身のプロセスを止めるには、管理者の権限が必要です(レッスン6)。

## CPUの切り替え

OSは、ほんの数ミリ秒ごとにCPUを使うプロセスを切り替えています。これを**スケジューリング**と言います。切り替えのとき、そのプロセスが「どこまで進んだか」を保存し、次に順番が来たときに続きから再開します。

切り替えが細かいので、人間には同時に動いているように見えます。ただし、1つのプロセスがCPUを独占しようとすると(`%CPU` が 99% のような状態)、他のプロセスの順番がなかなか回ってこなくなり、パソコン全体が重くなります。

## メモリ

プロセスが動くには、プログラムとデータを置く作業机が必要です。それが**メモリ**(RAM)です。ディスクが「本棚」なら、メモリは「机の上」です。机の上は本棚より小さいですが、手元にあるので速く読み書きできます。

OSはプロセスごとにメモリを割り当て、他のプロセスの領域を読み書きできないようにしています。この仕切りがあるおかげで、1つのアプリがおかしくなっても、他のアプリのデータが壊れることはありません。

メモリの使用状況は `free` で見られます。

```sh
free
```

机の上がいっぱいになると、OSは使っていないデータを一時的にディスクへ退避させます。これが **スワップ** です。本棚に戻しに行くのと同じで、退避と復帰のたびに遅くなります。「メモリが足りないとパソコンが重くなる」のはこのためです。

## まとめ

- ファイルとしてのアプリがプログラム、動いている状態がプロセス。PID で管理される
- `ps` で一覧、`kill PID` で終了
- CPUは1つずつしか処理できないが、OSが高速に切り替えて同時に見せている
- メモリはプロセスの作業机。プロセスごとに仕切られている。足りないとスワップで遅くなる
