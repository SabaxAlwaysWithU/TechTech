## 大きさが、動かすまでわからない

ここまでの配列は `int a[5];` のように、**書いたときに大きさが決まって**いました。でも、「読み込んだデータの件数だけ箱がほしい」のように、動かしてみるまで大きさがわからないことはよくあります。

そんなときは、プログラムの実行中に、OS(のメモリ管理)から必要な分だけメモリを**借ります**。

## スタックとヒープ

プログラムが使うメモリには、大きく2つの場所があります。

| | スタック | ヒープ |
| --- | --- | --- |
| 何が置かれるか | 関数の中の変数(ローカル変数) | `malloc` で借りたメモリ |
| いつ片付くか | 関数が終わると自動で消える | `free` で返すまで残る |
| 大きさ | 小さめ(数MBほど) | 大きく使える |

ローカル変数は、関数が終わると自動で片付きます。便利ですが、関数が終わったあとも使いたいデータや、大きなデータは置けません。そこでヒープを使います。

## malloc で借りて、free で返す

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int n = 5;
    int *a = malloc(sizeof(int) * n);
    if (a == NULL) {
        printf("メモリを借りられませんでした\n");
        return 1;
    }
    for (int i = 0; i < n; i++) {
        a[i] = i * 10;
    }
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
    free(a);
    return 0;
}
```

- `malloc(バイト数)` で、ヒープからそのバイト数を借りて、その**住所**を返す(`stdlib.h` が必要)
- 何バイト要るかは `sizeof(int) * n` のように計算する
- 借りられなかったときは `NULL` が返るので、必ず確かめる
- 借りたメモリは、ポインタを通して配列と同じように `a[i]` で使える
- 使い終わったら `free(a)` で返す

`malloc` で借りたメモリの中身は、まだ何も入っていない(ゴミのような値の)状態です。0 から始めたいときは、`calloc(個数, 1つの大きさ)` を使うと 0 で埋めて借りられます。あとから大きさを変えたいときは `realloc` を使います。

## 関数から、借りたメモリを返す

ヒープのメモリは、関数が終わっても残ります。だから、関数の中で作ったデータを、呼んだ側に渡せます。

```c
#include <stdio.h>
#include <stdlib.h>

int *make_squares(int n) {
    int *a = malloc(sizeof(int) * n);
    for (int i = 0; i < n; i++) {
        a[i] = i * i;
    }
    return a;
}

int main() {
    int *sq = make_squares(4);
    printf("%d %d %d %d\n", sq[0], sq[1], sq[2], sq[3]);
    free(sq);
    return 0;
}
```

借りたのは `make_squares` の中ですが、返すのは使い終わった `main` です。「誰が `free` するのか」を決めておくのが、C のプログラムを書くときの大事な約束になります。

逆に、ローカル変数の住所を返してはいけません。

```text
int *bad(void) {
    int a[3];        // スタックの上。関数が終わると片付く
    return a;        // 片付いた場所の住所を返してしまう
}
```

返した住所の先は、もう別の用途に使われるかもしれない場所です。

## 返し忘れ: メモリリーク

`free` を忘れると、借りたメモリはプログラムが終わるまで返されません。これを**メモリリーク**(メモリの漏れ)といいます。

```text
for (int i = 0; i < 1000000; i++) {
    int *tmp = malloc(1000);
    // tmp を使う
    // free(tmp); を忘れた
}
```

1回なら気づきませんが、ずっと動き続けるサーバーで少しずつ漏れていると、何日かたってメモリを使い切り、止まってしまいます。

## 返したあとに使う: こわれたポインタ

`free` したあとのメモリを使うのも、よくある事故です。

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int *p = malloc(sizeof(int));
    *p = 42;
    free(p);
    p = NULL;
    if (p != NULL) {
        printf("%d\n", *p);
    } else {
        printf("もう返したので使いません\n");
    }
    return 0;
}
```

`free(p)` のあとも、`p` には前の住所が残っています。そのまま `*p` を読み書きすると、もう別の用途に貸し出されたメモリをこわすかもしれません(**解放後の使用**)。`free` したらすぐ `p = NULL;` にしておくと、うっかり使う前に気づけます。同じメモリを2回 `free` するのも、同じく危険です。

## ほかの言語は何をしてくれているか

Python や JavaScript には `free` がありません。使われなくなったデータを自動で見つけて片付ける、**ガベージコレクション**という仕組みがあるからです。そのぶん、片付けの手間がかかる時間は、言語が決めます。

C は、それを全部自分でやる代わりに、いつ借りていつ返すかを完全に自分で決められます。OS や、ゲーム、組み込み機器のように、速さや、決まった時間で動くことが大事なところで C が使われ続けているのは、このためです。最近では、同じ速さのまま、メモリの事故をコンパイラが防いでくれる Rust のような言語も使われ始めています。

## まとめ

- ローカル変数はスタックに置かれ、関数が終わると片付く。大きさが動かすまでわからないものはヒープに借りる
- `malloc(バイト数)` で借りて住所を受け取り、`NULL` でないか確かめる。使い終わったら `free`
- 誰が `free` するかを決めておく。ローカル変数の住所は返さない
- `free` を忘れるとメモリリーク。`free` したあとに使うのも、2回 `free` するのも事故のもと
- Python や JavaScript はガベージコレクションが片付けてくれる。C は自分で管理する
